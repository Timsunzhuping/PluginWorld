dsh-persona-dafeiyu · 人设库插件

启用后，系统提示词里会注入当前选中的人设 —— 全局、按工作区或按会话，都不用每次手动粘贴。

  • 内置人设：大肥鱼、阿茶、听澜（写死在代码里，不可删除、不可覆盖；正文可以展开查看）。
  • 导入人设：在设置页里用文件导入或直接粘贴文本，自动生成可选条目。
  • 导出人设：自导入 / config 人设可一键存成 .md——格式与「导入」一致，导出的文件能原样再导入回来。
  • 设置页「人设」小节：查看当前人设、切换、启用 / 停用、重命名、删除、导入、导出。
  • 中英双语界面：设置页与输入框小条跟随 DSH 的界面语言切换（zh / en）； 内置人设的名字与简介按当前语言显示，用户自己导入的人设名照原样显示。
  • 免重启切换：人设段落的 text 是动态函数，提示词每次组装都会重新求值， 所以切换后下一个请求就用新文本，无需重启、无需重新加载插件。
  • 正文按需下发：状态接口只给元数据（内置人设额外带一句简介），点「查看全文」才拉那一条的正文。
  • 全局 / 工作区 / 会话三档生效范围：整个 profile 共用一个、按项目目录各用一个、 或只给当前会话单独挑一条；越细越优先，且三档可以叠着用。

安装

前置条件

  • Node.js ≥ 20
  • DSH —— 已实测的版本见文末「兼容性」

方式 A：从 npm 安装（推荐）

本包已发布到 npm，不需要克隆仓库、不需要构建。

界面上装：侧边栏 → 插件 → 添加插件 → 输入包名：

dsh-persona-dafeiyu

命令行装：

dsh plugin --profile <profile> add dsh-persona-dafeiyu

<profile> 换成你自己的 profile 名。DSH 随安装自带的模板只有 acp / web / headless / sdk / sdk-minimal，你自己建的那个叫什么就用什么。

本包是纯 JavaScript、没有构建脚本，所以不会触发 pnpm 的「允许运行构建脚本」提示—— 输入包名即可装好，这是最省事的方式。

方式 B：从源码目录安装（改代码时用）

git clone https://github.com/huaizhuanghub/dsh-persona-dafeiyu.git
cd dsh-persona-dafeiyu
(Get-Location).Path

最后一行打印的绝对路径，下面安装命令要用到。然后：

dsh plugin --profile <profile> add "<本仓库绝对路径>"

或者在插件页「添加插件」里填这个绝对路径。

本包没有运行时依赖（@deepseek-ai/* 全是 optional peer，由 DSH 运行时提供）， 所以克隆后不需要 npm install 就能直接跑自检。

两种方式都会把本包写进 profile 的 dsh.profile.bundles。

生效时机与「免重启」的边界

  • 切换人设不需要重启：那是运行中的插件按需重算段落文本，下一个请求立即生效。
  • 但插件代码本身（lib/index.js / lib/client.js）更新后，要让宿主与浏览器拿到新版本， 仍需重启 DeepSeek Harness（客户端 bundle 至少要刷新页面）。这是加载机制，不是人设切换。

安装位置提醒

本地目录安装是 link:（pnpm 建软链接指向本目录），所以别把本目录删掉再重启。 想彻底自包含，可以先 npm pack 出 tgz 再安装。

使用（设置 → 大肥鱼）

区域 能做什么
当前生效 看当前人设名、来源（内置 / 导入 / config）、启停状态、段落位置、字数、人设库文件路径；内置人设显示简介，自导入人设提示去列表看全文
生效范围 三档开关：全局 / 工作区 / 会话（越细越优先，见下一节）
工作区生效规则 列出已知的工作目录，每个目录一个下拉框挑人设，默认「跟随全局」；在某个项目里发过消息后，该目录就会出现
人设列表 每条显示名称 + 来源徽标 + 字数；可「设为当前」「启用 / 停用」；导入的还可以「重命名」「删除」（删除需二次确认）
内置人设 大肥鱼、阿茶、听澜：只读——没有删除 / 重命名按钮，列表里标注「内置人设不可删除或重命名」；正文可以展开查看
自导入人设 每条都有「查看全文」：按需拉取并展开完整提示词（含换行），再点收起；另有「导出」把正文存成 .md
导入人设 选 .md / .markdown / .txt 文件（自动填入正文与名称），或直接把提示词粘贴到文本框，点「导入」

正文展示的分工：

  • 正文一律按需拉取：/status 只给元数据，点「查看全文」才走 /persona?id= 取那一条的正文， 内置 / 自导入 / config 一视同仁。开启很多条人设时状态接口也不会被撑成几 MB。
  • 内置人设额外带一句简介：它们是插件自带的那几条，列表里直接说明是什么性格； 正文同样可以展开查看，但只读（不可删除、不可覆盖），也不提供导出—— 想改就先自己导入一份。

规则说明：

  • 「设为当前」会自动启用该人设（停用状态下点它就会恢复注入）。
  • 停用当前人设 → 系统提示词里不注入任何人设段落（状态显示「当前人设已被停用」）。
  • 停用非当前人设只影响它自己，当前人设照旧。
  • 删除当前人设会回落到大肥鱼。
  • 人设名不能为空、不能超过 60 字符、不能与其他人设重名。
  • 人设正文不能为空、上限 64,000 字符。

导入用的文件长什么样，见 examples/persona.example.md。

生效范围：全局 / 工作区 / 会话

人设可以整个 profile 共用一个、按项目目录各用一个，或只给当前会话挑一条。 三档不是互斥开关，而是越细越优先的阶梯：

会话档：会话选择 → 工作区选择 → 全局当前
工作区档：        工作区选择 → 全局当前
全局档：                        全局当前

好处：可以先给项目配好工作区人设，再按会话临时覆盖；清掉会话选择时自动落回工作区。

输入框上方的小条（全局 / 会话）

🐟 大肥鱼        [全局] [会话]          ← 全局：所有会话都用「当前」那条
🐟 阿茶 ▾        [全局] [会话]          ← 会话：显示本会话的人设，点名字弹出选择浮层
🐟 阿茶 · 工作区  [全局] [会话]          ← 工作区档：只显示状态，规则在设置页里配
  • 会话档下点人设名 → 弹出屏幕正中的选择浮层（注册在 DSH 的 shell.overlay 插槽）。 人设再多也只是浮层里滚动，不会把输入框旁边堆满；选完自动关闭，点遮罩空白处也能关。
  • 工作区档下小条不提供按钮——按目录逐条挑人设那件事在设置页里做。
  • 点 [全局] / [会话] 永远是切换生效范围本身，工作区档也能一键跳出。

设置页里的工作区规则

生效范围   [全局] [工作区] [会话]

工作区生效规则
  <项目目录>\backend     [阿茶      ▾]
  <项目目录>\frontend    [跟随全局  ▾]
  • 清单 = 人设库里已经挑过的目录 ∪ 本次进程里见过的目录。 宿主在每次组装提示词时从会话上下文里收集 cwd，所以一个目录要先在那里发过一条消息才会出现。
  • 每一行一个下拉框：选任意一条人设，或「跟随全局」。

通用规则

  • 选项全部来自设置页已导入的人设库——这个功能不会为会话 / 工作区新建人设。
  • 挑中的那条若被停用，自动往下一层回落。
  • 会话选择只活在进程内存里（DSH 重启即回落到工作区 / 全局），符合会话本身的临时性； 工作区选择与人设库一起持久化；「选哪一档」这个范围本身也是持久化的。

对应接口：set-mode（global / workspace / session）、set-workspace-persona （cwd + personaId）、set-session-persona（sessionId + personaId； personaId: null 表示清除）；GET /status?sessionId=<id>&cwd=<path> 会额外返回 该会话 / 该工作区的视角，以及最终生效的是哪一条（effective）。

人设库与接口

  • 持久化位置：<DSH_HOME>/storages/dsh-persona-dafeiyu/personas.json。 DSH_HOME 没设时退回 DSH 家目录（Windows 上是 %USERPROFILE%\.dsh\，类 Unix 上是 ~/.dsh/）， 代码里走 os.homedir() 动态求值、不写死任何绝对路径。 写入采用「临时文件 + 改名」，文件损坏时回退到空库而不会让插件挂掉。

  • 接口（都只接受回环请求）：

    方法 路径 作用
    GET /api/dsh-persona-dafeiyu/status 当前状态 + 人设列表（只有元数据，不含正文）+ 存储路径；带 ?sessionId=&cwd= 时另给会话 / 工作区视角与 effective
    GET /api/dsh-persona-dafeiyu/persona?id=<id> 按需取单条人设的完整正文（「查看全文」用；内置 / 导入 / config 都走这里）
    POST /api/dsh-persona-dafeiyu/mutate set-current / import / rename / remove / set-enabled / set-mode / set-workspace-persona / set-session-persona

    非回环访问返回 403，方法不对返回 405，请求体不是 JSON 返回 400，操作被拒时返回 { ok: false, error }（HTTP 仍为 200，错误语义在 body 里）。

  • 活体自测（端口以 DSH 启动时打印的地址为准）：

    Invoke-WebRequest http://127.0.0.1:<port>/api/dsh-persona-dafeiyu/status -UseBasicParsing

插件配置（可选）

在「插件」页选中 dsh-persona-dafeiyu 那一行改 config，或直接编辑 cordis.patch.yml：

字段 默认 含义
enabled true 总开关；关掉即完全不注册段落（设置页会显示「插件被 enabled: false 停用」）
prefix '' 自定义人设正文，在列表里作为一条 config 人设出现
personaFile '' 外部 Markdown 人设文件路径，同样作为一条 config 人设出现
suffix '' 追加在工具指导之后的人设后缀（order 对齐 DEPLOYMENT_PERSONA_SUFFIX = 10200）
order 未设 显式指定前缀段落顺序，覆盖默认的 0

prefix / personaFile 不是「最高优先级」，而是列表里的一个可选项（id 固定为 config）： 想用它就去设置页设为当前；清空配置它就从列表里消失。日常使用建议直接导入人设，不再动这两个字段。

完整示例见 examples/config.example.yml。

配置由 @deepseek-ai/schemastery 描述；本地 link: 安装时该模块可能解析不到， 插件会自动退回内置的最小 standard-schema，配置校验与默认值照旧生效，不会因为缺依赖而加载失败。

开发与自检

克隆下来不需要 npm install 就能验证：

npm test                     # 自检：宿主侧人设库 / 生效范围 / 回环接口 / 客户端 bundle 渲染
npm run privacy-check        # 本机信息自查：绝对路径、用户名、邮箱、密钥、公网 IP…
npm run privacy-self-test    # 自查脚本自己的自检：身份规则该报的报、不该报的不报
  • 自检把人设库隔离到临时 DSH_HOME，不碰你真实的人设库。
  • 全新克隆 / CI 上找不到 @deepseek-ai/schemastery 时，插件会退回内置兜底 schema， 自检会打印一行说明并照常全绿（退出码 0），所以 CI 无需任何安装步骤。
  • 改完内置人设正文后请务必跑一次 npm test：其中一组断言会给每条内置人设 取一段正文指纹，用来保证内置正文不会从状态接口泄漏出去。 新增内置人设时不用手改这些断言——它们是遍历 BUILTIN_PERSONAS 的， 但你必须同时补上 lib/client.js 里对应的中英词条，否则自检会直接报出来。

本机用户名是通用词时（root / user / test …）

privacy-check 会用「本机用户名」做一次大小写不敏感的裸词搜索，而容器、VPS、 CI 里的用户名常常就是 root 这类普通英文单词 —— 那会把 const root = path.resolve(…) 这种正常代码报成「本机用户名泄漏」，退出码 1 把 CI 打红，还给出改不对的建议。

所以身份规则分两层：

  • 够独特的名字（带数字 / 下划线，或够长的少见串）→ 照旧裸词全仓库搜索；
  • 通用词 → 跳过裸词，只保留路径形态匹配（用户目录路径里出现才报）。 这时报告开头会有一行提示说明「少了一层、以及为什么」，不会悄悄降级。

想验证这套判定是否符合预期，跑 npm run privacy-self-test（11 项，不起子进程、不读磁盘）。

更多约定见 CONTRIBUTING.md。

实现要点

  • 人设作为独立 prompt section（dafeiyu:persona）注册，不占用也不覆盖 DSH 自带的 deployment:persona-prefix 槽位，因此可以全局挂载，其它 preset 依旧能遮蔽它。
  • 默认顺序 = DEPLOYMENT_PERSONA_PREFIX（order 0）：第一方开场白之后、所有工具指导之前。
  • 段落以 interpolate: false + 函数 text 注册：函数每次组装被调用，返回当前人设正文； 停用或无人设时返回空串，空段落会被自动丢弃。
  • 内置人设同时受两层保护：代码里的 BUILTIN_PERSONAS 与读取存储时的保留 id 过滤 （磁盘上伪造同 id 的条目会被直接丢弃）。
  • 正文按需下发：/status 只给元数据（内置带 description 简介），点「查看全文」才走 /persona?id=；这样开启很多条人设时也不会把状态接口撑成几 MB。
  • 「当前该注入谁」由一个 resolvePersona() 解析（会话 → 工作区 → 全局的阶梯）； 提示词注入与状态接口的 effective 都调用它，所以界面显示与实际注入不会漂移。
  • 会话人设选择器注册在 shell.overlay（整帧浮层插槽），用 position: fixed 居中； 不往 document.body 追加 DOM。小条与浮层是两个独立插槽组件，用一个极简 store 联动。

界面语言（中 / 英）

界面文案走 DSH 的 locale 服务，字典命名空间是 personaDafeiyu，注册 zh 与 en 两份。

  • 语言跟随 DSH：在「设置 → 通用」里切换界面语言，本插件的设置页与输入框小条一起变， 不需要重启或刷新插件。字典在挂载后注册也会被认到。
  • 内置人设的名字与简介：宿主侧只有中文原文，界面按当前语言取插件字典里的词条 （personaNameDafeiyu / personaAboutTinglan 这一类），所以英文界面显示 Tinglan 而不是「听澜」。
  • 回退策略：字典里查不到某条（例如第三方语言包只翻了一半），界面回退到宿主给的原文， 而不是把键名（personaAboutTinglan）显示出来。
  • 用户数据不翻译：你导入的人设名按原样显示——中文名在英文界面上依旧是中文名。
  • 标点也随语言：「简介」这类「标签 + 值」的行用字典里的 labelSeparator： 中文是全角冒号 ：，英文是 : 。
  • 新增内置人设时：lib/index.js 的 BUILTIN_PERSONAS、lib/client.js 的 BUILTIN_LOCALE_SUFFIX 与 zh / en 两份词条要一起补，自检会强制检查。

隐私说明

本仓库已做过本机信息清理，不含开发者本机的绝对路径、用户名、主机名、邮箱或任何密钥：

  • 文档与注释里的路径一律写成占位符（<本仓库绝对路径>、<profile>、<port>、%USERPROFILE%）；
  • 代码里读路径一律走 os.homedir() / process.env.DSH_HOME 动态求值，不写死；
  • 没有需要外置的敏感配置：本插件不读任何 API Key、Token 或口令。 config 里唯一可能带本机信息的是 personaFile（外部人设文件路径）， 示例见 examples/config.example.yml，真实路径请留在本机、不要提交；
  • 人设库（personas.json）属于本地运行数据，已在 .gitignore 中排除；
  • 改动后请跑 npm run privacy-check 自查，CI 也会跑一遍。
