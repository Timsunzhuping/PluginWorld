dsh-ops

中文 | English

Windows DSH 的性能工具插件：提供独立 bash / PowerShell 7，并用 Rust 重写文件检索与批处理， 减少反复踩 PowerShell 报错所浪费的 token、时间和模型注意力。

tips：本项目的 ops 是广义 operations（运行操作）的缩写，代指本插件处于 dsh 和系统/代码/文件操作的基础工具位置。本项目不是 operations（运维）插件。

0.3.1 支持 Windows x64、Linux x64 与 macOS Apple Silicon（darwin-arm64），目标宿主 DSH 0.2.0-rc.2。原生 Rust 文件/PTC worker 按精确目标携带于 runtime/<platform>-<arch>/；PTC 默认关闭。Intel Mac、Windows ARM64 与 Linux ARM64 不在支持范围。Bash/PowerShell 7 二进制保持 Windows-only 可选依赖，Linux/macOS 使用宿主 Bash，不在 npm 安装时下载 Windows shell。见 Linux 适配、Apple Silicon 与 PTC。

核心特性

  • （全平台）使用 Rust 编写的一组工具，用于改善 AI 报错循环、强迫思考不交付、注意力涣散的问题，并以渐进式披露减少系统 prompt 的工具定义占用：加速任务运行，减少不必要的输入输出，减少报错率，以及提供与 DSH 对齐的权限机制。

    在自用 benchmark 中获得了

    • 97% token 减免（开启 ops 插件的 PTC 专用工具 对比 Windows 原装标准模式）
    • 65% token 减免（开启 ops 插件的 PTC 专用工具 对比 Linux 原装 PTC 模式）

    的成绩，并改善了在 DSH 运行的 AI 的智力表现。

  • （仅 Windows）提供独立 bash 5.3.15 和独立 PowerShell 7.6.6：优先使用 bash，必要时回退 pwsh 7，让你的 AI 不再和 PowerShell 打架 —— 不修改系统默认终端、PATH 或宿主原有 shell 工具名称，环境变量安全。Linux 上不随包提供 shell，直接使用发行版自带的 bash。

  • 独立的 Rust 原生文件工具与安全批处理（默认关闭，须显式启用），见 组件参考。

  • 未来会加入一系列 docx、pdf 处理轻量化的好用 Rust 工具，均可开关，不占用上下文。

执行顺序：工具包 → bash → PowerShell 7。

Linux 适配

dsh-ops 在 Linux x64 上与 Windows 侧能力对齐（除下面明确列出的部分）：原生 Rust worker 以 ELF 随包携带，文件工具（inspect_local_file / glob / grep / replace）与可选 PTC 组件（ops_batch / ops_result）在 Linux 上同样可用。

  • shell 组件的平台分野：Windows 上是随包固定摘要的 bash 5.3.15 / PowerShell 7.6.6 载荷与 Bash IPC 代理；Linux 上改为解析宿主发行版自带的 bash（config.bashPath → PATH → /bin/bash、/usr/bin/bash、/usr/local/bin/bash），不随包提供第二份 shell，也不提供 pwsh 覆盖层 —— 发行版的 bash 与其 libc/架构绑定，再塞一份反而多出供应链和许可负担。ops_bash 在两端都可用；受限模式必须由宿主沙箱（bwrap / Landlock）落实，沙箱缺失或无法约束时拒绝执行，不会退化成无约束运行。以 shell 为执行通道的后台组件仍仅 Windows；dsh-ops provision-shells 也仅 Windows，Linux 上会明确拒绝并指向 config.bashPath。
  • 构建与安装：见 Linux 构建与验证（English）—— npm run verify → npm run build:ptc → npm pack → dsh plugin add ./dsh-ops-0.3.1.tgz。
  • 平台差异已处理：替换文件时保留 mode/owner/POSIX ACL/xattr；目录 fsync 按 POSIX 语义；multiline 搜索跨行匹配；读取按编码字节与行数双重设界。
  • 默认拒绝读取凭据：文件工具（含 PTC 批处理）在 worker 被 spawn 之前就拒绝 ~/.ssh、~/.aws、~/.azure、~/.kube、.npmrc、DSH 凭据库等位置，遍历也按路径身份跳过这些目录，所以 glob 连私钥文件名都不会列出、grep 不会在其中匹配到任何内容；写入根收窄为本会话自己的 dsh-ops-session-<id> 临时目录（0700）。该行可用 denyCredentialReads: false 关闭，DSH_OPS_DENY_READ 只能加严、不能放松。Windows 侧等价的安全描述符（DACL）处理见 Windows 验证清单。
  • 验证记录：早期 Linux PR 的 Debian 13 测量属于贡献者记录，不替代最终集成版门禁；本版三平台结果与发布产物以 0.3.1 发布说明 及其链接的 Actions 运行为准。
  • 这些实测暴露并已修复的缺陷（Windows 同样受益）：替换丢失 mode/ACL/xattr、multiline 无法跨行、单行超长文件让读取整体失败、并发替换静默丢更新、硬杀残留临时文件、worker 无执行位时只报裸 EACCES。详见 0.3.1 发布说明 与 CHANGELOG。

快速开始

前置条件

  • Node.js ^22.19 || >=24（package.json 的 engines 要求）
  • Windows x64、Linux x64 或 macOS Apple Silicon；不支持 Intel Mac。pwsh 覆盖层仅 Windows，POSIX 使用宿主 Bash。
  • 目标 DSH 应用已初始化

安装

方式一：官方插件市场（推荐）

在目标 DSH 应用的插件市场中输入 npm 包名 dsh-ops，安装后选择启用。安装归属于当前运行的 profile，桌面端为 desktop。

方式二：npm 一键安装

npx --yes dsh-ops@latest install --profile desktop

必须显式选择目标 profile；tui 映射到 dsh-TUI 产品的 dsh-tui profile，不是旧的 tui 目录。请先初始化目标应用。

桌面端必须使用桌面应用自带的 CLI；默认探测 %LOCALAPPDATA%\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd。安装在其它位置时加 --dsh-cli "<安装目录>\resources\runtime\cli\bin\dsh.cmd"。

⚠️ node_modules/@dsh-ops/ 下没有 bash-win32-x64 不是安装损坏。 三个载荷都是精确钉版的可选依赖（optionalDependencies）：若你的 registry 未同步该平台包的对应版本，包管理器会静默跳过它——安装仍以退出码 0 结束，且不打印任何指向缺包的警告。

不要用 allowSystemShellFallback: true 绕过：那是安全姿态降级（改用未固定摘要的系统 bash），且首次升级启动的配置迁移会把它改回 false。

bashPath 仅在 danger-full-access 下生效：只读/工作区内修改模式只运行固定摘要的随包或 provision 的 bash，自带 Git for Windows 会按设计返回 EXECUTOR_UNAVAILABLE，不要靠它绕过受限模式问题。见 配置参考。

普通 DSH CLI 不能管理保留的 desktop profile；不要把它与桌面自带入口混淆。

详情与兜底办法见 常见问题。

卸载与查看状态

npx --yes dsh-ops@latest status --profile desktop
npx --yes dsh-ops@latest uninstall --profile desktop

把 desktop 换成 web 或 tui 即可。

组件

Bundle 声明四个组件，分别启停，首次安装默认开启前两个：

组件 介绍 默认 发布的工具
dsh-ops/shell 将默认终端改为 bash，以及 bash 覆盖不到时提供 PowerShell 7 开 ops_bash；宿主 pwsh 使用随包 PowerShell 7
dsh-ops/file 更快、更高性能、输出更精简更省 token 的 Rust 文件检索 开 四个文件工具
dsh-ops/background 为科研仿真、模型训练及其他长进程后台任务提供托管 关 启动、输出、列出、终止后台任务
dsh-ops/ptc 独立 Rust 安全批处理和有界结果引用，仅纯 PTC 会话加载 关 ops_batch、ops_result

“默认终端改为 bash”指模型提示优先使用 ops_bash，不修改系统默认终端、PATH 或宿主原有 shell 工具名称。

工具的完整参数、配置项与权限要求见 组件参考 与 配置参考。

配置迁移的完成标记：完成后重启/热加载不再覆盖；你之后主动改回 true 会被保留。不要删除迁移标记，否则会重新自检。
