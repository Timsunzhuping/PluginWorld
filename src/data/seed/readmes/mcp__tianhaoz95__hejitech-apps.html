HEJI projects monorepo

One public repo for several products. Each lives in projects/<name>/ with its own Cloudflare site/Worker, mobile and desktop apps, docs and release settings. They share one Supabase project, one npm workspace and the CI plumbing.

Layout

projects/<name>/        everything one product owns (apps, services, packages, site, docs)
  release.env           how scripts/cut_release.sh releases it
supabase/               the shared Supabase project: config, schemas/<name>/, one migrations/ history
scripts/cut_release.sh  releases one project: scripts/cut_release.sh <name> [patch|minor|major|x.y.z]
scripts/db_migration.sh new migration for one project; check_supabase.mjs keeps projects apart
scripts/check_isolation.mjs, graduation_check.sh   each project can leave for its own Supabase (supabase/GRADUATION.md)
pages/                  the GitHub Pages site for every app (npm run pages:dev); project docs come from projects/<name>/docs
.claude/skills/         agent skills: heji-new-project, heji-migrate-project, heji-candidate-review, heji-fix-ci, heji-new-skill, heji-archive-reports (.agents/skills/ links them for Codex, Antigravity, Gemini CLI, Cursor…)
.github/workflows/      <name>-*.yml per project
.github/actions/        apple-signing (shared), <name>-toolchain
package.json            npm workspaces: projects/*/packages/*, projects/*/services/*, projects/*/apps/*
tsconfig.base.json      shared TypeScript settings

npm install                 # every project's workspaces
supabase start              # shared local stack (ports 554xx)
npm run build:waypack       # per-project scripts: build:<name>, test:<name>, typecheck:<name> (waypack, weehours)

Adding a project

  1. Code in projects/<name>/: Node packages under packages/ or services/, apps under apps/ (any of them with a package.json is picked up by the workspaces; name them @<name>/…). Add build:/test:/typecheck:<name> scripts to the root package.json.
  2. Backend: projects/<name>/backend.env (copy Wee Hours'): which Supabase project it uses and the only files allowed to contain its coordinates. Projects share the HEJI project until they graduate to their own; keep that possible (supabase/GRADUATION.md). Database: its own Postgres schema (named after the project, so the folder name must be a valid identifier) and Storage bucket. Tables go in supabase/schemas/<name>/; generate migrations with scripts/db_migration.sh <name> <what>. Read supabase/README.md first: users, auth settings, the service key and the plan's quota are shared (that's the point). Wee Hours is the worked example of a non-legacy project.
  3. CI: .github/workflows/<name>-ci.yml with paths: covering projects/<name>/** and the shared root files (copy waypack-ci.yml). Release workflows trigger on release: published and must skip other projects' tags: if: startsWith(github.event.release.tag_name, '<name>-v'). Name its GitHub variables and secrets <NAME>_… (only the Apple team signing secrets are shared).
  4. Docs: projects/<name>/docs/ with an index.md (and optionally pages.json for the sidebar) appears on the site as /<name>/; add a card for the app to pages/index.md.
  5. Releases: projects/<name>/release.env (copy Waypack's) with TAG_PREFIX="<name>-v" and LATEST=false. Waypack owns the repo's "latest" release: its installed Mac apps update from releases/latest.
  6. Cloudflare: a Workers Builds project per Worker, root directory = repo root, deploy command cd projects/<name>/services/<worker> && npm run deploy, build watch paths projects/<name>/*.
  7. Apple/Google: per-app bundle IDs under com.hejitech.*; signing secrets in apple-signing are team-wide and reusable.
