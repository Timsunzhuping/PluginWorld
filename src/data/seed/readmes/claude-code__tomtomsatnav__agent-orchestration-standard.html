AOS Dashboard

A read-only live monitor for Claude Code. It shows what your sessions and subagents are doing (agents, tasks, tokens, cost, file conflicts, alerts) as a streaming graph in the browser, a terminal view (aos-dash), an MCP server and a status line. It never starts, stops or steers agents. Local-only, zero dependencies.

Looking for orchestration (planning goals, launching and managing workers)? That is a different, separate and experimental project: aos-orchestrator, opt-in. This dashboard can display its goals, nothing more.

Install the dashboard

Needs Node 18+ and the Claude Code CLI (claude on your PATH; the installer checks and stops with a message if not). No dependencies to install.

git clone https://github.com/tomtomsatnav/agent-orchestration-standard && cd agent-orchestration-standard
make install        # ~4 s. Builds, installs the local plugin, links `aos-dash`, starts the monitor
make doctor         # checks the whole setup and tells you what to fix
make                # lists every target

make install changes only: the Claude Code plugin (user scope, via claude plugin install), a symlink ~/.local/bin/aos-dash (add that folder to your PATH if aos-dash is not found), a small notifier app under ~/.claude/plugins/data/, and a monitor process on port 4318 (make install PORT=4328 uses another port). make uninstall reverses it. make stop and make uninstall stop only the monitor on PORT (4318 unless you pass PORT=). make doctor shows "no hook log yet" until you start a Claude Code session; that is normal.

Then start a new Claude Code session and open http://127.0.0.1:4318 (the page is empty until a session sends events; aos-dash is the same view in the terminal). The graph's Streams button (or Q) cycles Full / Quiet / Lines; Lines draws no particles and stops per-frame redraws, for the lowest overhead (measured). Local-only, read-only; hooks never log prompts, file contents or tool output, but do log event and tool names, working-folder and edited-file paths, transcript paths and a redacted short task description (full list: plugin/README.md). Status: personal project, macOS-first. MIT License.

Lowest overhead: run aos-dash for the terminal view (no browser tab, no animation), and set the graph's Streams button to Lines.

GOALS panel

The GOALS button and the "Needs you" badge stay hidden until a goal exists or the control server answers on 4319. The GOALS panel only displays goals from the separate, experimental orchestrator, read from disk, but approving, pausing and starting goals needs the control server from aos-orchestrator (aos-orch serve, port 4319). Without it the panel is read-only. The files the dashboard reads are described in docs/orch-state-contract.md.
