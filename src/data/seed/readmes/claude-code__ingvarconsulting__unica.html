Unica

Unica (Ю́ника) — публичный плагин Codex и Claude Code для разработки на 1С:Предприятии. Он добавляет навыки и один MCP-сервер unica, через который агент создаёт и проверяет метаданные, формы, роли, СКД, внешние обработки и отчёты, запускает 1С и ищет BSL-код.

Оба хоста получают один и тот же каталог плагина: манифесты лежат рядом, а .mcp.json определяет корень плагина по той переменной, которую подставляет конкретный хост.

Требования

  • один из агентов:
    • Codex CLI;
    • Claude Code;
  • стандартный Git, включая Git for Windows на Windows;
  • платформа 1С только для операций, которым реально требуется запуск 1С.

Поддерживаемые версии платформы 1С

Версия платформы Статус Что это означает
8.5.1.x, 8.5.4.x Планируется Хотим добавить в ближайшее время.
8.3.27.x Поддерживается Unica поддерживает все актуальные релизы ветки 8.3.27.
8.3.26.x и ниже Не планируется Помогаем мигрировать на 8.3.27. Если вам действительно нужна более старая версия, создайте issue и опишите причину — нам важно понимать такой сценарий.

Установка

Codex

codex plugin marketplace add IngvarConsulting/unica-marketplace --ref main
codex plugin add unica@unica

После установки откройте new Codex task: список навыков и MCP-конфигурация фиксируются на границе новой задачи, а не подменяются в уже работающей сессии.

Claude Code

claude plugin marketplace add IngvarConsulting/unica-marketplace
claude plugin install unica@unica

Затем выполните /reload-plugins либо начните новую сессию. Навыки становятся доступны с префиксом плагина, например /unica:meta-info.

Доставка ядра и движков

При старте MCP bootstrap скачивает только ядро unica из релиза IngvarConsulting/unica для текущей ОС и архитектуры. После запуска ядро доставляет нужный движок из закреплённого релиза unica-toolchain перед первым вызовом, которому этот движок действительно нужен. Архив, ассет и каждый файл проверяются по SHA-256; неполная или повреждённая загрузка не получает маркер готовности.

Если доставка движка не завершилась внутри ограниченного окна, вызов возвращает work.status=working и не запускает обработчик. Повторите тот же предметный вызов: отдельного публичного инструмента установки нет. Параллельные вызовы делят одну загрузку.

Корень кэша зависит от хоста:

Хост Каталог кэша
Codex $CODEX_HOME/unica/runtimes, при стандартном CODEX_HOME — ~/.codex/unica/runtimes
Claude Code ${CLAUDE_PLUGIN_DATA}/runtimes, по умолчанию — ~/.claude/plugins/data/unica-unica/...; этот каталог переживает обновление плагина

Внутри корня каждая неизменяемая поставка лежит по адресу <artifact>/<version>--<asset-sha256>/<target>. Поэтому пересобранные байты с той же версией не перезаписывают прежний движок. Для образа, который после сборки работает без сети, заранее доставьте ядро и все движки:

<plugin-root>/bootstrap/bin/<target>/unica-bootstrap prefetch --plugin-root <plugin-root>

Обновление

Codex

codex plugin marketplace upgrade unica
codex plugin remove unica@unica
codex plugin add unica@unica

Затем откройте new Codex task: уже работающая сессия не загрузит обновлённые навыки и MCP-конфигурацию.

Отдельной команды codex plugin upgrade в поддерживаемом CLI нет, поэтому переустановка плагина после обновления каталога является намеренным шагом.

Claude Code

claude plugin marketplace update unica
claude plugin update unica@unica

Затем выполните /reload-plugins.

Переход со старых версий

Узнайте свою версию:

codex plugin list

В строке unica@... смотрите столбец VERSION.

Ваша версия Что делать
0.3.0–0.7.4 Запустите скрипт миграции
0.7.5 и новее Выполните обычное обновление

Актуальные инструменты и их аргументы перечислены в описании публичного API.

Для версий 0.3.0–0.7.4 на macOS и Linux:

curl -fLO https://github.com/IngvarConsulting/unica/releases/download/v0.7.8/install-unica.sh
sh install-unica.sh --ref v0.7.8

Для версий 0.3.0–0.7.4 в Windows PowerShell:

Invoke-WebRequest https://github.com/IngvarConsulting/unica/releases/download/v0.7.8/install-unica.ps1 -OutFile install-unica.ps1
.\install-unica.ps1 -Ref v0.7.8

Для версий 0.7.5 и новее:

codex plugin marketplace upgrade unica
codex plugin remove unica@unica
codex plugin add unica@unica

Если скрипт завершился ошибкой, предыдущая установка уже будет восстановлена.

Начиная с v0.8.0, текущий пакет не содержит исполняемого кода старых-миграций: для старых версий поддерживается только переход через замороженную версию v0.7.8.

Удаление

Codex:

codex plugin remove unica@unica
codex plugin marketplace remove unica

Claude Code:

claude plugin uninstall unica@unica
claude plugin marketplace remove unica

Проверенные исполняемые-кэши можно оставить для повторной установки. Их ручное удаление не является частью обычного процесса удаления.

Разработка

Рекомендуемое окружение разработчика, настройка rust-analyzer для кодовых агентов и установка навыков MCP Server Dev описаны в руководстве для контрибьюторов. Реестр приёмочных сценариев поверхности и покрытие операций — в docs/acceptance-scenarios.md.

Для разработки под Codex используется отдельный marketplace unica-dev:

git clone https://github.com/IngvarConsulting/unica.git
cd unica
scripts/dev/install-local-unica.sh

Под Claude Code каталог плагина подключается напрямую, без маркетплейса:

claude --plugin-dir ./plugins/unica

На Windows x64 запускайте этот скрипт из Git Bash, входящего в 64-битный Git for Windows. Для локальной сборки нужны Python 3.12 или новее, стабильный Rust с нативным toolchain MSVC, а также Microsoft C++ Build Tools и Windows SDK.

WSL сохраняет Linux-семантику и собирает linux-x64. MSYS2 и Cygwin не входят в поддерживаемые shell для этого installer; используйте Git Bash.

Исходный .mcp.json запускает cargo run; локальный скрипт собирает инструменты только для текущей машины. Официальный пакет остаётся тонким: skills, assets, три bootstrap-бинарника и runtime-manifest.json, без ядра и движков.

Репозиторий

  • plugins/unica/skills/ — прикладные навыки 1С;
  • crates/unica-coder/ — единый MCP runtime unica;
  • crates/unica-bootstrap/ — проверяемая доставка, кеш и запуск ядра;
  • plugins/unica/third-party/tools.lock.json — версии внутренних инструментов.
