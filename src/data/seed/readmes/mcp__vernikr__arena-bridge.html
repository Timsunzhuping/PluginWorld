arena-bridge

Облачный ИИ-агент получает управление вашим компьютером — и только с вашего разрешения.

npm i -g arena-bridge  →  arena-bridge setup  →  вставьте готовый промпт в чат с агентом

Что это

Полное дерево функциональности — в feature-tree.md.

Облачный агент (Arena.ai Agent Mode, Claude, Cursor, любой MCP-клиент) работает в песочнице с выходом в интернет, но не имеет доступа к вашему компьютеру. arena-bridge — это маленький HTTP-сервис на вашей машине: он слушает только localhost, выставляется наружу туннелем (cloudflared / ngrok / Tailscale) и отдаёт агенту инструменты, которые вы ему разрешили:

  • файлы и шелл — прочитать, найти, изменить, запустить;
  • Chrome — свой браузер агента (headless или с окном) или ваш настоящий Chrome на порту 9222;
  • macOS-десктоп — скриншоты, мышь, клавиатура, приложения (через Peekaboo);
  • процессы — фоновые дев-серверы с чтением вывода.

Всё, что меняет состояние, проходит через гейт подтверждений, а каждое действие пишется в журнал. Без вашего arena-bridge approve агент ничего не сделает. Наблюдать за машиной можно без подтверждений, а работать «без вопросов» — внутри окна доверия, которое вы открываете сами.

Быстрый старт

Одна команда ставит и командную строку, и нативное приложение для macOS:

curl -fsSL https://raw.githubusercontent.com/vernikr/arena-bridge/main/install.sh | sh

Или по отдельности:

npm i -g arena-bridge          # только командная строка
pip install arena-bridge       # то же самое на Python

Приложение macOS можно скачать и без терминала — в каждом выпуске лежат готовые сборки: Apple silicon · Intel. Распаковать и перетащить в «Программы».

# 1. один раз: создать конфиг, проверить машину, поднять API + туннель
arena-bridge setup --root ~/projects --root ~/Documents

# 2. скопировать блок «Paste this into the agent chat» и вставить его в чат с агентом

macOS и Gatekeeper. Приложение подписано локально, поэтому при первом запуске система может сказать «нельзя открыть, так как разработчик не проверен». Обойти это можно без терминала: правый клик по Arena Bridge в «Программах» → Открыть → Открыть. Через терминал: xattr -dr com.apple.quarantine "/Applications/Arena Bridge.app".

setup печатает готовый промпт и публичный URL. Дальше — просто говорите агенту задачу.

Туннель под присмотром: если cloudflared/ngrok упадёт, мост поднимет его заново и сам напечатает новый публичный адрес. Постоянный адрес вместо случайного — arena-bridge tunnel --bin ngrok --domain <зарезервированный домен>.

Нужен туннель? Поставьте cloudflared (brew install cloudflared или бинарник в /usr/local/bin). Можно и через ngrok — arena-bridge tunnel --bin ngrok; с сохранённым токеном и зарезервированным доменом публичный адрес остаётся постоянным, и промпт агенту не нужно копировать заново: arena-bridge tunnel --bin ngrok --authtoken <token> --domain <name>.ngrok-free.dev.

В фоне, чтобы не открывать терминал

Мост можно поднять как службу macOS — он стартует вместе с системой, переживает закрытие терминала и поднимается заново после сбоя:

arena-bridge service install                                   # облако, случайный адрес
arena-bridge service install --bin ngrok --domain mymac.ngrok-free.app   # постоянный адрес
arena-bridge service status                                    # состояние и текущий URL
arena-bridge url                                              # текущий публичный адрес
arena-bridge service uninstall

arena-bridge service install   # launchd: стартует вместе с системой, URL всегда живой
arena-bridge url                # текущий публичный URL

Python

pipx install arena-bridge       # или: pip install arena-bridge
arena-bridge setup --root ~/projects

Как выбрать инструмент

прочитать страницу chrome_snapshot ({"mode":"ax"} — роли и имена, {"mode":"text"}, {"mode":"html"})

Управление Chrome

Свой минимальный CDP-клиент внутри пакета: ни puppeteer, ни playwright не нужны.

// браузер агента: свой профиль, без ваших cookie
{"tool": "chrome_launch", "args": {"headless": true, "url": "https://example.com"}}
// прочитать структуру страницы
{"tool": "chrome_snapshot", "args": {"mode": "ax"}}
// кликнуть и ввести
{"tool": "chrome_click", "args": {"text": "Sign in"}}
{"tool": "chrome_type", "args": {"selector": "input[name=q]", "text": "hello", "submit": true}}
// скриншот
{"tool": "chrome_screenshot", "args": {"path": "shot.png"}}
  • headless: true — без окна (по умолчанию), headless: false — видимое окно;
  • профиль отдельный (~/.arena-bridge/chrome-profile-*), в ваши сессии агент не попадает;
  • действия в браузере агента подтверждения не требуют — это его песочница.

Ваш настоящий Chrome (с вашими логинами) — через chrome_attach:

open -na "Google Chrome" --args --remote-debugging-port=9222 --user-data-dir="$HOME/.chrome-debug"

{"tool": "chrome_attach", "args": {"port": 9222}}

Любое действие в присоединённом браузере требует локального подтверждения. Инструментов чтения cookies и localStorage нет.

Управление macOS-десктопом

Через Peekaboo (это же использует и MCP-режим Peekaboo):

{"tool": "mac_see", "args": {"app": "Safari", "mode": "window"}}  // скриншот + id элементов
{"tool": "mac_element", "args": {"name": "Save"}}                // найти кнопку по названию
{"tool": "mac_click", "args": {"on": "B3"}}                      // клик по id из mac_see
{"tool": "mac_set", "args": {"on": "B2", "value": "hello"}}      // вписать значение напрямую
{"tool": "mac_type", "args": {"text": "hello", "submit": true}}
{"tool": "mac_key", "args": {"key": "cmd+s"}}
{"tool": "mac_menu_click", "args": {"app": "Safari", "item": "Save"}}  // пункт меню по названию
{"tool": "mac_wait", "args": {"name": "Saved", "timeout": 20}}        // дождаться результата
{"tool": "mac_apps", "args": {}}                                  // что запущено
{"tool": "mac_permissions", "args": {}}                           // чего не хватает в macOS

Установить Peekaboo: brew install peekaboo (или бинарник в /usr/local/bin/peekaboo). Проверено с Peekaboo 4.9 (4.3 тоже работает, но синтаксис команд обновлён под 4.9). macOS asks for Screen Recording and Accessibility for the Arena Bridge app; without them screenshots and clicks fail. See macOS permissions.

Что даёт доступ Accessibility

macOS отдаёт приложениям два разных слоя: картинку экрана и Accessibility API — дерево элементов интерфейса с названиями, ролями и значениями. Второй слой полезен агенту сильнее:

по картинке через Accessibility API
как найти кнопку «Сохранить» угадать координаты mac_element {"name":"Сохранить"} → точный элемент
как нажать клик по координате, может промахнуться mac_click {"on":"<id>"} — по самому элементу
как вписать текст свайп, фокус, клавиатура mac_set {"on":"<id>","value":"..."} — без фокуса и без клавиш
как открыть «Файл → Экспорт» перемещать курсор по меню mac_menu_click {"item":"Экспорт"} — по названию
как убедиться, что получилось смотреть скриншот mac_wait {"name":"Готово"} — ждать появления
как заполнить поле свайп + клавиатура + фокус mac_set {"on":"<id>","value":"..."} — значение пишется в элемент
чужой ввод и фокус мешает вам действия уходят в фоновое окно

Практический вывод: с выданным Accessibility агент работает заметно точнее и тише. Разрешение даётся один раз в Системные настройки → Конфиденциальность и безопасность → Универсальный доступ (for the Arena Bridge app, see macOS permissions). mac_permissions shows the current state.

Журнал работы с артефактами

Каждый вызов записывается: аргументы, результат, время выполнения. Рядом с журналом хранятся доказательства — снимки экрана, деревья Accessibility, деревья меню, список рабочих столов.

arena-bridge audit                 # последние вызовы
arena-bridge audit artifacts       # сохранённые файлы (скриншоты, деревья)
arena-bridge audit <id>            # одна запись целиком
arena-bridge audit prune           # удалить старые артефакты (по умолчанию старше 14 дней)
arena-bridge audit dir             # где всё это лежит

Агенту доступно то же самое: audit_log (вызовы) и audit_artifact (сам артефакт — PNG в base64 или дерево Accessibility в JSON), а также GET /audit и GET /audit/artifact?entry=<id>&file=<name>. Полезно, чтобы оглянуться назад: что было на экране и что находилось в интерфейсе.

Связь с Telegram

Агент может писать вам в Telegram и читать ваши ответы — даже если вы сейчас не в чате с ним.

# один раз: привязать бота (токен от @BotFather и ваш chat id)
arena-bridge telegram setup --token 123456:AA... --chat-id 190771108

# проверить связь
arena-bridge telegram test

# посмотреть, что вам писали
arena-bridge telegram inbox

Что это даёт:

  • notify_user — агент пишет вам: «сделал», «нужно ваше решение», «вот результат». С {"wait_for_reply": true} вызов ждёт вашего ответа прямо в Telegram.
  • telegram_inbox — агент читает то, что вы написали боту: ответы, правки, поручения.
  • telegram_status — бот, список чатов, число непрочитанных сообщений.
  • Подтверждения из Telegram. Когда агенту нужно ваше «да», мост сам пишет вам: /approve <id> — разрешить, /deny <id> — отказать. Из терминала тоже можно: arena-bridge approve <id>.

Как это устроено и что защищено:

  • токен бота лежит только в ~/.arena-bridge/config.json (права 0600); агент этот файл прочитать не может — он в списке защищённых путей;
  • писать можно только в те чаты, что перечислены в --chat-id (по умолчанию — ваш);
  • не больше 20 сообщений в минуту, одно сообщение — до 4000 символов;
  • входящие сообщения мост слушает сам (служба launchd — автоматически), входящие лежат в ~/.arena-bridge/telegram/.

Одно уточнение: для бота api_id/api_hash не нужны — они пригодятся только для режима «личного аккаунта» (MTProto), который пока не включён.

Нативное приложение для macOS

Окно, в котором всё видно и всё управляется: статус, пуск/стоп, подтверждения, журнал.

git clone https://github.com/vernikr/arena-bridge.git
cd arena-bridge/macos/ArenaBridge
./build.sh                                   # → dist/Arena Bridge.app
cp -R "dist/Arena Bridge.app" /Applications/

Нужен только Swift из Xcode Command Line Tools (xcode-select --install), Xcode целиком не требуется. Собирается под текущую архитектуру: ARCH=x86_64 для Intel, ARCH=arm64 для Apple Silicon. Готовые сборки для обеих архитектур появляются в каждом выпуске на GitHub (см. «Быстрый старт»), собирать самому не нужно.

Блок в окне Что делает
Статус запущен/остановлен, версия, режим, число инструментов, публичный адрес, уведомления, Telegram
Управление «Запустить» / «Остановить» (служба ai.arena.bridge), «Настроить…», «Скопировать промпт агенту»
Доверенное окно «Открыть на 3 ч» / «Закрыть» и статус «действует ещё 2:59»
Подтверждения ожидающие запросы агента с кнопками «Разрешить» / «Разрешить на 3 ч» / «Отклонить»
Журнал команды с аргументами, клик по скриншоту или ax-tree открывает его целиком, «Сохранить…» в файл (с ax-tree)

Окно следит за машиной само: статус, подтверждения и доверенное окно обновляются каждые несколько секунд, журнал — чуть реже. Кнопка обновления (⌘R) есть на всякий случай.

Когда агенту нужно решение, приложение показывает системное уведомление macOS «Approval needed» — в строке меню и в центре уведомлений. Внутри окна запрос тоже виден сразу, в карточке «Подтверждения».

«Настроить…» собирает конфиг, службу и запуск одной кнопкой: туннель (ngrok/cloudflared), зарезервированный домен, authtoken, папки для агента, Telegram (токен бота и chat id).

Иконка приложения лежит в macos/ArenaBridge/Resources/AppIcon.png; build.sh сам собирает из неё .icns и кладёт в бандл. Вокруг знака прозрачно — на светлом фоне иконка не белая.

macOS permissions

The bridge takes screenshots and clicks through the helper arena-bridge-agent inside Arena Bridge.app, so macOS needs two permissions for it:

  • Screen Recording (System Settings → Privacy & Security → Screen & System Audio Recording)
  • Accessibility (System Settings → Privacy & Security → Accessibility)

Check them at any time with arena-bridge permissions (exit code 3 when something is missing) or with the mac_permissions tool. The app shows a warning on the Control card when either permission is missing. Click Fix… to open the step-by-step guide.

Grant the permissions (about 3 minutes)

The screen runtime is the helper arena-bridge-agent inside the app (/Applications/Arena Bridge.app/Contents/Helpers/arena-bridge-agent). macOS checks that helper, so it is the entry to switch on. Each missing permission has its own Fix … button on the Control card, which opens a guide with that permission's steps.

  1. Click Fix Screen Recording… on the Control card. Click the path in the guide to copy it.
  2. Click Open Screen Recording settings in the guide. In the list, click +. If + is grey, click the lock at the bottom left and enter your Mac password.
  3. Press ⌘⇧G, paste the path, press Return, then click Open. Switch on arena-bridge-agent.
  4. If macOS asks you to quit Arena Bridge, click Later. Do not choose Quit & Reopen yet.
  5. Repeat steps 1–4 for Accessibility with its own Fix Accessibility… button.
  6. Quit Arena Bridge with ⌘Q, open it again, and click Check again in each guide. The warning disappears when both permissions are granted.

Harder cases:

  • The switch is on, but the app still says "missing". The entry is stale, which usually happens after an update. Select arena-bridge-agent, click −, then +, and add it again.
  • The app is not in /Applications. Move it there first. macOS ties permissions to the exact file location.
  • Still missing after all of the above. Restart the Mac, open Arena Bridge, and click Check again.

Keep the permissions across updates

The Keep permissions after updates… button in each permission guide opens the same steps inside the app.

macOS identifies an app by its signature. Builds without your own certificate are ad-hoc signed, and macOS can reset their permissions after every rebuild. To avoid this, create a certificate once:

  1. Open Keychain Access (Spotlight → "Keychain Access").
  2. Menu Keychain Access → Certificate Assistant → Create a Certificate…
  3. Name: Arena Bridge Local. Identity Type: Self-Signed Root. Certificate Type: Code Signing. Click Create, then Done.
  4. In Keychain Access, choose login under Keychains and search for Arena Bridge Local. Three items appear: a certificate, a public key and a private key. Double-click the item whose Kind is certificate, expand Trust, set When using this certificate to Always Trust, close the window, and enter your password.
  5. Build with it: ARENA_SIGN_IDENTITY="Arena Bridge Local" bash macos/ArenaBridge/build.sh. Install the app and grant the permissions once more. Later builds signed the same way keep them.

Release downloads are ad-hoc signed, so after installing one, follow the grant steps again. The Control card warning and arena-bridge permissions show the state after every update.

Как переименовать

Имя приложения лежит в трёх местах, и тесты следят, чтобы они совпадали:

Файл Что там
src/app.mjs APP_NAME, APP_ID, SERVICE_LABEL, AGENT_NAME — для командной строки
arena_bridge/app.py то же самое для Python
macos/ArenaBridge/Sources/AppInfo.swift то же самое для приложения; build.sh берёт имя отсюда

Фоновая служба в «Системных настройках → Вход» называется так же, как приложение, а не «node» или «python»: запускает её помощник внутри бандла приложения, а без приложения — небольшой скрипт ~/.arena-bridge/Arena Bridge.

Подтверждения в Telegram: кнопки

Под сообщением «Approval needed» появляются нативные кнопки:

Approve once      Approve for 3h      Deny
  • Approve once — разрешить этот запрос и всё;
  • Approve for 3h — разрешить и открыть доверенное окно на 3 часа для этого же инструмента (команды больше не спрашивают);
  • Deny — отклонить.

Кнопки работают и в приложении на Mac, и в Telegram; сообщение в Telegram после нажатия переписывается на итог. Прежние команды /approve <id> и /deny <id> тоже работают.

Доверенное окно: работать без подтверждений

arena-bridge trust --for 2h                                   # всё, на 2 часа
arena-bridge trust --for 30m --tools bash                     # только команды
arena-bridge trust --for 1h --paths ~/projects/my-app         # только эта папка
arena-bridge trust --status
arena-bridge trust --status --json                            # для приложений и скриптов
arena-bridge trust --off
  • окно снимает требование подтверждения, но не снимает политику путей: за пределами roots и в защищённых каталогах по-прежнему PROTECTED;
  • --paths ограничивает доверие конкретными папками; bash под такое ограничение не попадает — чтобы доверять командам, укажите --tools bash явно;
  • окно живёт локально (~/.arena-bridge/trust.json), агент открыть его не может;
  • после истечения срока подтверждения возвращаются сами, а все действия остаются в журнале.

Отдельные браузерные «кабинеты» агента

Агенту можно выдать несколько независимых профилей браузера — например «рабочий», «клиентский», «тестовый». В каждом свои входы, и они переживают перезапуск моста.

arena-bridge browser login work       # открыть Chrome с профилем «work»
# вы логинитесь в нужные сайты и закрываете окно — входы сохраняются
arena-bridge browser list             # какие профили есть
arena-bridge browser close work       # закрыть окно этого профиля

Агент открывает тот же профиль через chrome_launch {"profile":"work"} — уже с вашими входами. Каталог профилей агент тоже видит: chrome_profiles.

browser login специально запускает обычный Chrome без отладочного порта и флагов автоматизации: Google и другие сайты отказывают во входе браузеру, который выглядит управляемым извне. Отладочный доступ появляется только потом, в агентском chrome_launch, когда вход уже выполнен. Старое имя browser open оставлено как алиас той же команды.

Ваш собственный Chrome (на порту 9222, с вашими сессиями) доступен отдельно — через chrome_attach; любые действия в нём требуют подтверждения.

Что беспокоит Как решается
окно агента занимает экран по умолчанию агент работает в фоне; видимое окно можно сделать маленьким и в углу: chrome_launch {"headless":false,"width":900,"height":700,"x":-920,"y":40}
агент перехватывает фокус и курсор действия в нативных приложениях идут «в фон» — в нужное окно, без переключения на вас; курсор двигается только по вашей явной просьбе
окно агента на вашем рабочем столе macOS умеет несколько рабочих столов: агент переключается на отдельный стол через mac_space_switch, вы остаётесь на своём
нужен отдельный «второй монитор» в macOS виртуальный монитор штатно не создаётся; сторонние утилиты (BetterDisplay, DisplayLink) умеют — тогда окно агента всегда там, где вы не работаете
нужен полностью независимый курсор и стол только отдельная виртуальная машина; на 16 ГБ и Intel 2019 года она заметно тормозит и съедает 30–60 ГБ — как правило, не нужно

Рекомендация для ноутбука с 16 ГБ и Intel 2019: отдельные профили браузера + фоновый режим + при необходимости второй рабочий стол macOS. Полноценная виртуальная машина того не стоит.

Безопасность

Токен Кто знает Что позволяет
token агент вызывать инструменты по HTTP/MCP
deviceToken только устройство подключаться к хабу
localToken только вы подтверждать запросы и открывать окно доверия
  • Агент не может одобрить сам себя: POST /approvals/:id требует локальный токен.
  • Пути ограничены: всё вне roots — PROTECTED. Защищённый список по умолчанию включает ~/.ssh, ~/.aws, ~/.arena-bridge, ~/.npmrc, профили браузеров, ключи.
  • Подтверждения: bash, запись, удаление, управление вашим Chrome и десктопом ждут arena-bridge approve <id>. Подтверждать нужно, пока вызов ожидает решения. После timeout или expired запрос закрыт и его approval_id больше не принимается. Для продолжения откройте arena-bridge trust --for 1h и повторите вызов один раз либо согласуйте новый вызов, который пользователь подтвердит во время ожидания.
  • Журнал: ~/.arena-bridge/audit.log (JSONL) — кто, что и когда вызвал.
  • Транспорт: сервер слушает 127.0.0.1, наружу — только туннель с HTTPS.
arena-bridge rotate            # новый агентский токен (действует мгновенно)
arena-bridge rotate --device   # новый девайсный токен
arena-bridge audit -n 50       # что происходило

Частые проблемы

Симптом Что делать
port 8787 is already in use остановите старый экземпляр (Ctrl+C) или arena-bridge start --port 8788
туннель не поднимается cloudflared по умолчанию использует QUIC и может быть заблокирован — arena-bridge tunnel --protocol http2 (это поведение по умолчанию)
агент не видит файлы проверьте arena-bridge doctor и roots в ~/.arena-bridge/config.json; вне roots всё равно PROTECTED
APPROVAL_PENDING при timeout/expired старый запрос закрыт: согласуйте новый вызов или попросите открыть arena-bridge trust --for 1h
скриншоты не работают arena-bridge permissions — выдайте Arena Bridge Screen Recording и Accessibility (see macOS permissions)
peekaboo_not_found поставьте Peekaboo или укажите путь: arena-bridge init + peekabooPath в конфиге
