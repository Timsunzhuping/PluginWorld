MisakaNet

mcp-name: io.github.Ikalus1988/misakanet

The same failure, paid for twice.

A pip install times out behind a corporate proxy. An agent finds the fix. Days later the same timeout appears on another machine, under another model — and is debugged from scratch, because the fix was never written down anywhere the next agent looks.

MisakaNet is that place: a git-backed failure memory. Every lesson is a Markdown file in this repository — graded by evidence, reviewed like code, retrieved by an agent instead of guessed at. You fail once; the next agent does not.

Agent-native interfaces: MCP server (8 tools), WebMCP, llms.txt, A2A discovery via .well-known/agent-card.json.

Your first five minutes

1. Ask it something you have actually broken. No client installed? This curl is the whole interface:

curl -sS https://misakanet.org/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json' \
  -H 'MCP-Protocol-Version: 2025-06-18' -H 'Origin: https://misakanet.org' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"name":"misakanet_search","arguments":{"query":"database is locked","top":3}}}'

2. Read what came back. A hit returns the lesson, its evidence_level, and its path — open the file and read the fix before running any command in it. A miss returns no_match plus a ready-to-call intake: the corpus saying it does not know this one yet.

3. Check the trust signal, not the tone. E0–E3 say how far a lesson was verified; E4 is the one nobody can write or vote into.

What is MisakaNet?

Git-backed failure memory for AI coding agents. An error shows up → the agent searches → it applies a fix somebody already verified → if nothing matches, the miss becomes an intake, and the intake becomes a lesson for the next agent.

Every lesson is a Markdown file: reviewed like code, graded by evidence, retrieved with BM25 over the Python standard library. No vector database, no embedding model, no server unless you want one.
Lessons failure-recovery knowledge base, open and auditable under lessons/
Domains rag · devops · fanuc · docker · feishu · mcp · network · ci · wsl · windows …
Evidence E0 intake → E1 reviewed → E2 reproduced → E3 CI verified → E4 observed reuse by two or more distinct clients
It is not It is
❌ a general memory system ✅ a failure-recovery knowledge layer
❌ an agent runtime ✅ a searchable lesson database
❌ a vector database / RAG stack ✅ BM25 keyword search, stdlib only (Python ≥ 3.10 still required)
❌ a skill marketplace ✅ debugging knowledge from real sessions
❌ a retrieval benchmark ✅ a corpus graded by evidence; the benchmark we have is paused

What it answers — and what it does not

MisakaNet answers for the failures it has indexed, and only those. When nothing matches the reply is no_match plus a ready-to-call intake — the corpus saying "not this one yet", not a dead end.

Lesson vs Skill

A skill teaches an agent how to do something; a lesson records what went wrong before and how not to fail again. MisakaNet is only the second thing. → FAQ

Where it is today

  • The numbers that move are badges, on purpose: the Lessons badge renders data/badges/lessons.json, regenerated by update-badges.yml, so it can lag a run but is never a hand-typed total.
  • The top of the evidence ladder is empty, and this page says so. E4 needs an observation — two distinct clients actually retrieving a lesson — and the corpus has none yet (distribution, regenerated and checked by CI).
  • Search is BM25, so it matches words, not meaning. A failure described in vocabulary the corpus has never seen is a miss, and no retriever tuning fixes a corpus gap — which is why a miss returns no_match plus an intake instead of an empty page.
  • Reported gaps arrive faster than they are triaged. The intake queue is the honest bottleneck.

Benchmark: what it measured, and why it is paused

One narrow question: when you hand a model a lesson, how much of that lesson comes back? The metric is lesson_hit_rate — the share of the injected lesson's commands reproduced in the answer. Read the setup before the number: the scenario in this benchmark is each lesson's own title, the injected lesson is that same lesson, no retrieval call is made, and correctness is not checked. It measures the recitation half of RAG: necessary for MisakaNet to help, and not evidence that search finds anything.

The run is paused. Two independent runs of ≈500 scenarios each on 2026-09-22: 46.1% with the lesson pasted in, 23.3% without. What remains is the last snapshot plus its dated record — docs/benchmarks/latest.json.

Take part

1. Report a failure the corpus does not have. Search first, then call misakanet_submit_intake — no account, no email, no token, a five-line report is enough. It becomes a tracked issue.

2. Reuse a lesson and leave the trace. A "this helped" vote is recorded as an E3 hint, not as proof. The proof is quieter: your retrieval is counted, anonymously, as one more distinct client.

What you get back: attribution. A lesson cites the intake that produced it (source:, provenance.issue:), and the pipeline can emit a receipt naming the lesson and its evidence level.

Nothing here is a bounty: this repository pays nothing and promises nothing. Some issues carry third-party reward banners added by our own automation; we do not administer them — see Contributing.

How to use it

npx @misaka-net/misakanet-setup installs MisakaNet into your assistant's own config — the same command for every client. The ten supported clients, and what each one gets, are in the install page. Verify an install with npx @misaka-net/misakanet-setup --verify; undo it with --uninstall. Reads are anonymous and unlimited; registration is for writing (why). Node ≥ 18 for the installer, Python ≥ 3.10 for the library and stdio server.

The two-package trap (it cost a real install failure, #1849)

  • @misaka-net/misakanet-setup (npm) is the installer — it has a bin, no plugin entry. Use it to teach your assistant to search.
  • misakanet (npm) is the DSH / Codex plugin — dsh plugin --profile web add misakanet.
  • This repository (git) is also a Claude Code plugin marketplace — /plugin marketplace add Ikalus1988/MisakaNet.
  • misakanet (PyPI) is the stdio MCP server — python3 -m misakanet.server.
  • misakanet-core (PyPI) is the library (stdlib-only BM25) — from misakanet.search import search_lessons.

Use it as a GitHub Action

When a workflow fails, the action searches the lessons and comments the closest match on the pull request (optionally reporting the new error). Published on GitHub Marketplace.

on:
  workflow_run:
    workflows: ["CI"]                # your CI workflow's name
    types: [completed]
permissions:
  actions: read                      # read the failing job's log (required)
  pull-requests: write               # post the comment
  issues: write                      # the comment endpoint is issues.createComment
jobs:
  intake:
    if: ${{ github.event.workflow_run.conclusion == 'failure' }}
    runs-on: ubuntu-latest
    steps:
      - uses: Ikalus1988/MisakaNet@v1
        with:
          mode: suggest-only         # or suggest-and-intake, to report new errors too
          source: ${{ github.repository }}

Security

⚠️ Sandbox your agent before executing retrieved commands. Lessons are community-contributed — review before running. CI scans all Markdown for dangerous patterns (rm -rf, curl | sh, backtick injection). See SECURITY.md and LIMITATIONS.md.
