zames_pro

A terminal coding agent that drives real web chat LLMs (DeepSeek, Qwen, …) through a browser — no API key required.

English | Русский

A terminal coding agent that works on top of real web chat LLMs (chat.deepseek.com, chat.qwen.ai, …) through Playwright. In spirit it is similar to Claude Code / Codex CLI: it starts in the current directory, reads and edits files, runs commands, and commits to git.

No API key required — it drives a DeepSeek or Qwen web chat like a regular user through a real (headless) browser.

Quick start

npm install -g zames_pro   # Chromium for Playwright is downloaded automatically
cd your-project            # any folder the agent should work in
zames                      # sign in once, then describe your task

There is no API key and no per-token bill: zames signs in to your own chat.deepseek.com or chat.qwen.ai account in a real (headless) Chromium and drives the web chat like a regular user. The first launch asks for your login once (the session is stored in ~/.zames/profile for DeepSeek or ~/.zames/qwen-profile for Qwen); after that just run zames and type a task in plain language:

❯ refactor the config loader and add a test for the new default

While the agent works you can keep typing — a message sent mid-task is queued and runs right after it, in the same chat. Esc aborts the current generation, /help lists commands, /exit quits.

How it works

zames does not call the model API. It launches a headless Chromium with a persistent profile, signs in to a chat web app like a human, types the task into the chat box, and reads the answer back.

Two chat backends are available, switched with /provider <deepseek|qwen>: DeepSeek (chat.deepseek.com, the default) and Qwen (chat.qwen.ai). The switch is live — zames closes the current backend and opens the other one in place, no restart needed. Each keeps its own persistent profile (~/.zames/profile and ~/.zames/qwen-profile), so switching never signs the other one out.

In text: you type a task → zames sends the system prompt plus the task into the active chat web app (DeepSeek or Qwen) → the model answers → zames parses the tool call, runs the tool locally, feeds the result back, and prints the final answer for you.

Key pieces:

  • The answer is read from the raw network stream (SSE), not the rendered DOM, so tool-call JSON with template strings and escapes survives intact.
  • A persistent per-provider profile (~/.zames/profile for DeepSeek, ~/.zames/qwen-profile for Qwen) keeps you signed in; the headless User-Agent is patched so the site's CDN does not 403 the login.
  • A send throttle (15 s on DeepSeek, ~1 s on Qwen, which tolerates rapid sends) keeps the web chat's rate limit happy during long tool-heavy runs.
  • The agent is sandboxed to the directory it was started in — no tool can read or write above it.

Features

  • Tools like Claude Code / Codex — Read, Write, Edit, Bash, Glob, Grep, plus MultiEdit, ApplyPatch, LS, TodoWrite, git and web tools. Every edit is backed by /undo.
  • Runs while you keep typing — queue messages during a task; they run right after it, in the same chat (like typing during generation on the web).
  • Plan mode — /plan (or --plan) drops all mutating tools, so the agent can investigate the code without touching the tree.
  • Project context — reads AGENTS.md, MEMORY.md, skills (SKILL.md) and custom commands from the repo and ~/.zames, the same idea as Codex / Claude Code.
  • Subagents — the Task tool delegates a self-contained sub-task to an agent in its own separate chat (isolated context), which returns only a report, so heavy research does not flood the main context. On by default; tune with browser.subagents / browser.maxSubagents.
  • MCP support — plug in external tool servers (e.g. @playwright/mcp).
  • Scheduling — /loop, /cron and /jobs repeat tasks on a timer.
  • Bilingual UI — Russian / English (/config lang).

Why zames?

  • No API key, no per-token bill — it uses your own DeepSeek or Qwen chat account, not the paid API. Good for long, tool-heavy tasks.
  • Same workflow as Claude Code / Codex — tools, AGENTS.md, skills, MCP and slash commands, so it feels familiar from day one.
  • Runs unattended — headless by default, resumable sessions, and /loop plus /cron for scheduled work.
  • Local-first — the browser profile, credentials and logs never leave your machine, and the agent is sandboxed to the project directory.

Requirements

  • Node.js >= 20
  • An account on the chat you want to use — DeepSeek (chat.deepseek.com, the default) or Qwen (chat.qwen.ai). Qwen also works in guest mode for a few messages. On first launch zames asks for your login in the terminal (and stores it in ~/.zames/config.json after a successful sign-in, so a later logout is handled automatically without asking you again). You can also sign in manually in the browser window when the browser is headed.

Signing in

The browser runs headless by default. When the active backend requires a sign-in, zames:

  1. reuses the session stored in the persistent profile (~/.zames/profile for DeepSeek, ~/.zames/qwen-profile for Qwen) if it is still valid;
  2. otherwise signs in automatically with the saved credentials (browser.auth.username / browser.auth.password);
  3. otherwise asks you for the login/password in the terminal (in a TTY) and, after a successful sign-in, remembers them for next time;
  4. otherwise falls back to a manual sign-in hint.

To sign in by hand (for example, if the site shows a captcha), run with a visible window:

zames --headed

The --headless flag (the default) and headless: true in the config keep the browser without a window; --headed / headless: false show it.

Headless works out of the box: a headless Chrome normally advertises a HeadlessChrome/... User-Agent that the site's CDN blocks with a 403, so zames strips that marker before loading the page (keeping the real engine version). You do not need --headed just to log in.

Credentials and toggles can also be edited from /config (browser.auth.username, browser.auth.password, browser.auth.saveSession).

Switching providers (DeepSeek / Qwen)

zames can drive either DeepSeek (chat.deepseek.com, the default) or Qwen (chat.qwen.ai):

/provider qwen      # switch to Qwen (persisted) — applied live, no restart
/provider deepseek  # switch back
/provider status    # show the active provider / model / login state
/provider login     # (re)run the sign-in check
/model              # list Qwen models
/model qwen3.7-plus # pick one

Notes:

  • The switch is live: zames closes the current backend and opens the other one in place, so no restart is needed. The two backends use separate persistent profiles (~/.zames/profile for DeepSeek, ~/.zames/qwen-profile for Qwen), so switching never signs the other one out.
  • A chat id belongs to ONE backend, so the new provider opens a fresh chat. If the previous chat had messages they are summarized and posted as a handoff with the next task; an empty chat is switched silently.
  • Qwen works in guest mode without an account, but a guest is limited to a handful of messages per day; for long agent runs sign in (email / Google / GitHub — no phone required). zames auto-logins from the saved credentials or asks in the terminal, exactly like DeepSeek. /model changes the Qwen model at runtime.
  • File attachments on Qwen go through the mode menu's Upload attachment item; DeepSeek uses its own paperclip.
  • /doctor shows the active provider and the UI health of that provider's page.

Usage

Go to your project folder and run:

zames

The agent works inside the directory it was started in and cannot leave it (sandbox).

While the agent is working you can keep typing: press Enter to queue a message (it is sent right after the current task, in the same chat), or Esc / Ctrl+C to abort the current generation. This mirrors typing during generation on the web chat.

Input line

The prompt is a small line editor with persistent history:

  • ↑ / ↓ — walk the message history (saved in ~/.zames/history.json, so it survives a restart); inside a multiline message the arrows move between lines.
  • Ctrl+R — incremental reverse search over the history (bash-style): type to filter, Ctrl+R for older matches, Enter to accept, Esc to cancel.
  • Ctrl+_ — undo the last edit in the input line (a fat-fingered Ctrl+U / Ctrl+K is recoverable).
  • Ctrl+U — clear the line, Ctrl+K — delete to end of line, Ctrl+W — delete the word before the cursor, Ctrl+←/Ctrl+→ — move by words.
  • \ + Enter, Ctrl+J, Ctrl+Enter or Shift+Enter — insert a newline.
  • / + Tab — slash-command hints and completion.
  • !command — run a shell command directly, bypassing the model (like Claude Code's bash mode). The same sandbox guard as the Bash tool applies, so a direct command cannot leave the project either.

Full-screen mode adds dialog navigation, so a long answer can be read and selected without leaving the terminal:

  • mouse wheel — scroll the dialog (never the input history; history is arrow keys only). Selecting text needs Shift+drag, the standard TUI convention.
  • PgUp / PgDn — scroll the dialog half a screen.
  • Home / End — jump to the very top / bottom of the dialog (only while the input line is empty; with text typed they move the caret as usual).
  • To copy a LARGE block, use /export (writes the whole session as Markdown) or the transcript file (/transcript shows the path) — the terminal's own drag-select cannot reach past one screen.

Set NO_COLOR=1 to disable colors (a calm default palette is used otherwise).

Images and files

You can paste an image or a file into the input line (Ctrl+Shift+V / Shift+Insert or the terminal's own paste). zames saves it under <project>/tmp and shows a marker in the line - [image#1] for images, [file#1] for other files - then uploads the real file to the chat together with your message. These are the same formats the DeepSeek / Qwen web chat accepts (PNG, JPEG, GIF, WEBP, BMP, SVG and the usual document types).

Pasting an image works when the terminal sends it as a data: URL or as a base64 blob with a recognizable image signature. You can also paste a path to a local file (drag a file into the terminal or copy its path); if the file exists it is attached, otherwise the text is inserted as usual.

Press Ctrl+V (or use an empty paste) and zames reads the image straight from the clipboard: Linux via wl-paste (Wayland) or xclip/xsel (X11), macOS via pngpaste, Windows via PowerShell. The needed Linux tools are installed automatically on npm install (best-effort, through the detected package manager). If no image is found, zames says so and reports which tool it tried, instead of staying silent.

Machine-readable output (scripts / CI)

For one-shot runs (--task) the agent can emit its event stream as JSON lines on stdout, keeping all human text on stderr:

zames --task "summarize the diff" --output-format jsonl

Each line is one event (tool_call, tool_result, assistant_final, ...), so it pipes straight into jq:

zames --task "..." --output-format jsonl \
  | jq -r 'select(.type=="assistant_final") | .message'

Tools

The agent has the same style of tools as Claude Code / Codex CLI:

  • File tools — Read, Write, Edit, Bash, Glob, Grep. Read returns raw content by default; pass numbered=true to get cat -n-style line numbers (for reference only — do not paste them into Edit).
  • Extra tools — LS (list a directory), MultiEdit (several edits to one file applied atomically), TodoWrite (session task checklist), ApplyPatch (multi-file patch in Codex's V4A format: *** Begin Patch … *** End Patch).
  • Git — GitStatus, GitDiff, GitLog, GitShow, GitBranchList, GitAdd, GitCommit, GitPush.
  • Web — WebFetch, WebSearch.
  • Service — respond (final answer to the operator, ends the task).

All file tools stay inside the working directory (sandbox). Write/Edit and MultiEdit/ApplyPatch make a backup (undo) before touching a file.

Можно также вставить путь к локальному файлу (перетащите файл в терминал или скопируйте его путь); если файл существует — он прикрепляется, иначе текст вставляется как обычно.</p> <p>Нажмите Ctrl+V (или сделайте пустую вставку), и zames прочитает картинку прямо из буфера обмена: Linux через wl-paste (Wayland) или xclip/xsel (X11), macOS через pngpaste, Windows через PowerShell. Нужные Linux-утилиты ставятся автоматически при <code>npm install</code> (best-effort, через определённый пакетный менеджер). Если картинка не найдена, zames сообщит об этом и напишет, какой инструмент пробовал, вместо молчания.</p> <h3>Опции</h3> <pre><code>zames --task <текст задачи> zames --chat <id> zames --new-chat zames --resend-prompt zames --dir <path> zames --headless zames --headed zames --plan zames --output-format jsonl zames --debug zames --version zames --help </code></pre> <h3>Машиночитаемый вывод (скрипты / CI)</h3> <p>Для одноразовых запусков (<code>--task</code>) агент может выдавать поток событий как JSON lines в stdout, оставляя весь человеческий текст в stderr:</p> <pre><code class="language-bash">zames --task "summarize the diff" --output-format jsonl </code></pre> <p>Каждая строка — одно событие (<code>tool_call</code>, <code>tool_result</code>, <code>assistant_final</code>, …), так что это сразу пайпится в <code>jq</code>:</p> <pre><code class="language-bash">zames --task "..." --output-format jsonl \ | jq -r 'select(.type=="assistant_final") | .message' </code></pre> <h2>Инструменты</h2> <p>У агента тот же стиль инструментов, что в Claude Code / Codex CLI:</p> <ul> <li><strong>Файловые</strong> — <code>Read</code>, <code>Write</code>, <code>Edit</code>, <code>Bash</code>, <code>Glob</code>, <code>Grep</code>. <code>Read</code> по умолчанию отдаёт сырое содержимое; передайте <code>numbered=true</code>, чтобы получить нумерацию строк в стиле <code>cat -n</code> (только для справки — не вставляйте её в <code>Edit</code>).</li> <li><strong>Дополнительные</strong> — <code>LS</code> (список директории), <code>MultiEdit</code> (несколько правок одного файла атомарно), <code>TodoWrite</code> (чек-лист задач сессии), <code>ApplyPatch</code> (мультифайловый патч в формате V4A от Codex: <code>*** Begin Patch</code> … <code>*** End Patch</code>).</li> <li><strong>Git</strong> — <code>GitStatus</code>, <code>GitDiff</code>, <code>GitLog</code>, <code>GitShow</code>, <code>GitBranchList</code>, <code>GitAdd</code>, <code>GitCommit</code>, <code>GitPush</code>.</li> <li><strong>Web</strong> — <code>WebFetch</code>, <code>WebSearch</code>.</li> <li><strong>Служебный</strong> — <code>respond</code> (финальный ответ оператору, завершает задачу).</li> </ul> <p>Все файловые инструменты остаются внутри рабочей директории (песочница). <code>Write</code>/<code>Edit</code> и <code>MultiEdit</code>/<code>ApplyPatch</code> делают резервную копию (undo) перед изменением файла.</p> <h2>Слэш-команды</h2> <p>Введите / в промпте для подсказок (Tab дополняет). Кроме команд сессии и конфига (/new, /chats, /resume, /cd, /status, /config, /undo, /transcript, /mcp, /skills, /memory, /init, /reload, /debug-dom, /help, /exit) есть несколько в духе Claude Code / Codex CLI:</p> <ul> <li>/diff [--staged] — показать git-диф рабочего дерева (--staged для индекса).</li> <li>/diffstat — сводка изменений одной строкой (<code>git diff --stat</code>).</li> <li>/context — показать, что загружено в промпт (AGENTS.md, MEMORY.md, навыки, пользовательские команды) и размер системного промпта.</li> <li>/retry — отправить последнюю задачу в тот же чат заново (удобно после обрезанного или пустого ответа).</li> <li>/rename <title> — задать заголовок текущей сессии (виден в /sessions).</li> <li>/copy — скопировать последний ответ ассистента в буфер обмена ОС.</li> <li>/cost (алиас /usage) — статистика сессии: задачи, вызовы инструментов, длительность и размер контекста в токенах (у DeepSeek — <code>accumulated_token_usage</code>, у Qwen — <code>input_tokens</code>).</li> <li>/export [file] — записать транскрипт сессии в Markdown-файл (по умолчанию zames-export-<stamp>.md).</li> <li>/doctor — диагностика node, git, конфига, браузера, буфера обмена, MCP и активного провайдера чата (плюс состояние UI его страницы).</li> <li>/provider <deepseek|qwen> — сменить бэкенд чата (применяется сразу, без перезапуска); /provider status показывает активный провайдер/модель/вход; /provider login повторно проверяет вход. /model [id] покажет или выберет модель Qwen на лету.</li> <li>/add-dir <path> — проверить дополнительную директорию (песочница фиксируется при старте; для записи туда перезапустите с --dir).</li> <li>/resume <n> (после /chats) и /resume-id <id> — открыть чат и НАПЕЧАТАТЬ его диалог в терминал, чтобы восстановленный контекст был виден. Показываются только последние 20 сообщений (<code>RESTORED_HISTORY_LIMIT</code>). /last открывает последний чат текущей директории без поиска; /sessions показывает сохранённые сессии с их относительным возрастом.</li> <li>/help <command> — полное описание одной команды (например, <code>/help diff</code>) вместо всего списка.</li> <li>/review [focus] [--staged] — попросить агента проверить незакоммиченные изменения и сообщить находки (без правок кода).</li> <li>/plan [on|off] — режим плана (только чтение). Пока он включён, мутирующие инструменты (Write/Edit/MultiEdit/ApplyPatch/Bash, GitAdd/GitCommit/GitPush) убраны из набора, чтобы агент изучал код, не трогая дерево. Стартовать в нём можно с <code>--plan</code>.</li> <li>/compact — попросить активный бэкенд сжать текущий чат в передаточное резюме, затем открыть НОВЫЙ чат, заново отправить системный промпт и положить резюме как перенесённый контекст. Используйте, когда контекст разрастается.</li> <li>/goal <условие> — задать <strong>условие завершения</strong> (как в Claude Code). Агент сразу начинает работать над ним и продолжает запускать новые ходы, пока отдельная модель-оценщик не признает условие выполненным. Цель снимается автоматически при достижении (или если оценщик признал её недостижимой), либо командой <code>/goal clear</code>. Условие хранится в <code><project>/.zames-goal</code> (git-ignored) и восстанавливается при следующем запуске. <code>/goal</code> без аргумента показывает текущее состояние.</li> <li>/loop <interval> <task> — повторять задачу периодически (например, <code>/loop 10m run the tests</code>). /cron "<min> <hour> <dom> <month> <dow>" <task> — запуск по расписанию. /jobs [rm <id>|clear] перечисляет и останавливает их. Сработавшая задача попадает в ту же очередь сообщений, что и ваш ввод, так что выполняется, когда агент свободен (никогда посреди генерации), и всё равно соблюдает троттлинг отправки.</li> <li>/thinking [on|off] и /web [on|off] — переключить режим размышления / веб-поиска. В <strong>DeepSeek</strong> это тумблеры «Deep thinking» / «Smart search»; в <strong>Qwen</strong> — это режим размышления (Thinking / Fast) и пункт «Web search» в меню «+». Их (а также /queue, /jobs, /goal, <code>/config <sub></code>) можно использовать, ПОКА агент работает — они не трогают текущую генерацию.</li> <li>/queue [clear] — показать или очистить сообщения, ждущие отправки после текущей задачи.</li> </ul> <p>Контекст в токенах показывается и вживую: в строке статуса над вводом слева спиннер/текст, справа — контекст (например, <code>125k · 13%</code>, процент от 1M контекста). Он ОКРАШЕН по уровню заполнения: зелёный ниже 50%, жёлтый 50-80%, красный выше 80%. Значение приходит из счётчика токенов провайдера (у DeepSeek — <code>accumulated_token_usage</code>, у Qwen — <code>input_tokens</code>) и скрыто до первого ответа.</p> <h2>Контекст проекта, навыки и память</h2> <p>Как в Codex / Claude Code, zames читает инструкции проекта и переиспользуемые процессы из вашего репозитория и из <code>~/.zames</code>.</p> <ul> <li><strong>AGENTS.md</strong> — инструкции проекта. Положите его в корень репозитория (или в любую родительскую папку рабочей директории). Глобальные инструкции живут в <code>~/.zames/AGENTS.md</code> (и <code>~/.claude/CLAUDE.md</code>). Запустите <code>/init</code>, и агент изучит проект и напишет AGENTS.md на основе реальных команд сборки/тестов и соглашений (<code>/init --force</code> перезапишет существующий файл).</li> <li><strong>MEMORY.md</strong> — долговечные заметки, переживающие сессии. Агент дописывает сюда полезные факты; можно править вручную или добавить из промпта через <code>/remember <text></code>.</li> <li><strong>Навыки</strong> — папка с файлом <code>SKILL.md</code> (YAML-фронтматтер: <code>name</code>, <code>description</code>, опционально <code>allowed-tools</code>, <code>user-invokable</code>) плюс любые вспомогательные файлы. Ищутся в <code>.zames/skills/</code>, <code>.claude/skills/</code>, <code>.agents/skills/</code>, <code>skills/</code> и <code>~/.zames/skills/</code>. Агент читает тело только когда задача совпадает с описанием. Список — <code>/skills</code>; вызов — <code>/<skill-name></code>.</li> <li><strong>Пользовательские команды</strong> — <code>.md</code>-файлы в <code>.zames/commands/</code> (или <code>.claude/commands/</code>). Поддерживают подстановки <code>$ARGUMENTS</code> / <code>{{args}}</code> и вызываются как <code>/<command-name></code>.</li> </ul> <p>Навыки и пользовательские команды видны в списке автодополнения «/» и в <code>/help</code>.</p> <pre><code>/skills список найденных навыков /memory показать действующие AGENTS.md / MEMORY.md /remember <text> дописать долговечную заметку в MEMORY.md /init [--force] проанализировать проект и создать AGENTS.md </code></pre> <h2>MCP (внешние инструменты)</h2> <p>zames может использовать инструменты с серверов <a href="https://modelcontextprotocol.io">MCP</a>. Главный пример — @playwright/mcp: он даёт агенту настоящий браузер (navigate, click, snapshot, type, ...) поверх того, который zames уже использует для чата DeepSeek или Qwen.</p> <p>Положите файл конфига (той же формы, что в Claude Code / Cursor):</p> <ul> <li><code>~/.zames/mcp.json</code> — глобальный</li> <li><code><project>/.zames/mcp.json</code> — на уровне проекта (поздние файлы побеждают)</li> <li><code><project>/.mcp.json</code> — привычное имя MCP</li> </ul> <pre><code class="language-json">{ "mcpServers": { "playwright": { "command": "npx", "args": ["-y", "@playwright/mcp@latest", "--headless", "--isolated"] } } } </code></pre> <p>ВАЖНО: держите MCP-браузер изолированным. @playwright/mcp по умолчанию использует ТУ ЖЕ директорию профиля, что и zames (~/.zames/profile). Если запустить его без --isolated (или без собственного --user-data-dir), MCP-браузер и браузер агента подерутся за один профиль, и чат DeepSeek покажет «Something went wrong when opening your profile». Всегда передавайте --isolated, как в примере выше. Серверы бывают и удалёнными ("url": "https://...", "transport": "sse"). Их инструменты видны агенту как <code>server__tool</code> (например, <code>playwright__browser_navigate</code>) и перечисляются в <code>/mcp</code> и <code>/status</code>. Сервер, который не смог подключиться, пропускается с предупреждением и никогда не роняет агента.</p> <h3>Рекомендованные серверы (проверены)</h3> <p>Несколько небольших полезных серверов, протестированных вживую с zames (на обоих бэкендах — DeepSeek и Qwen):</p> <ul> <li><p><strong>Context7</strong> (<code>@upstash/context7-mcp</code>) — подтягивает АКТУАЛЬНУЮ документацию библиотеки (для конкретной версии) до того, как агент пишет код, вместо устаревших знаний из обучения. Инструменты: <code>resolve_library_id</code>, затем <code>query_docs</code>. Проверено вживую на DeepSeek И Qwen: агент вызвал оба инструмента и получил актуальный API Zod. Именно его стоит подключить первым.</p> <pre><code class="language-json">{ "context7": { "command": "npx", "args": ["-y", "@upstash/context7-mcp@latest"] } } </code></pre> </li> <li><p><strong>Sequential Thinking</strong> (<code>@modelcontextprotocol/server-sequential-thinking</code>) — один инструмент <code>sequentialthinking</code>, дающий модели явный пересматриваемый план перед действием; полезно для длинных многошаговых задач.</p> </li> <li><p><strong>Memory</strong> (<code>@modelcontextprotocol/server-memory</code>) — локальный граф знаний (9 инструментов) для долговременных фактов между чатами. ВНИМАНИЕ: у zames уже есть <code>MEMORY.md</code> + <code>AGENTS.md</code>; подключайте, только если нужен граф с запросами.</p> </li> </ul> <p>Держите набор МАЛЕНЬКИМ: каждый сервер грузит описания своих инструментов в контекст модели. Добавляйте, когда почувствовали нехватку, а не заранее.</p> <h2>Конфигурация</h2> <p>Глобальный конфиг: <code>~/.zames/config.json</code> Локальный (на проект): <code>.zamesrc.json</code></p> <p>Просматривать и менять настройки можно не выходя из агента — командой <code>/config</code>. Запустите её без аргументов, чтобы открыть интерактивное меню (↑/↓ — навигация, Enter — изменение, <code>d</code> — сброс, <code>q</code> — выход). Булевы и enum переключаются на месте; числа и строки открывают ввод.</p> <pre><code>/config интерактивное меню настроек /config list показать все изменяемые настройки /config get <path> показать настройку /config set <path> <value> изменить настройку /config reset <path> сбросить настройку к дефолту /config path показать пути файлов конфига /config lang <ru|en> переключить язык интерфейса и агента </code></pre> <p>Примеры:</p> <pre><code>/config set maxIterations 20 /config set browser.deepThinking true # DeepSeek Deep thinking (медленно; рассуждения скрыты) /config set browser.webSearch false # DeepSeek Smart web search /config lang en </code></pre> <p>Изменения пишутся в проектный <code>.zamesrc.json</code> и применяются сразу (где это возможно без перезапуска).</p> <h3>Язык</h3> <p><code>/config lang ru</code> или <code>/config lang en</code> переключает и язык интерфейса (справка, сообщения, спиннер), и язык, на котором агент вам отвечает. Локаль хранится в <code>ui.locale</code> в файле конфига.</p> <p>Данные агента хранятся в <code>~/.zames</code>: профиль браузера, логи, история undo, сессии.</p> <h2>FAQ</h2> <p><strong>Это официальный продукт DeepSeek или Qwen?</strong> Нет. zames управляет публичными веб-интерфейсами <code>chat.deepseek.com</code> / <code>chat.qwen.ai</code> через настоящий браузер, как обычный пользователь. Он не связан ни с DeepSeek, ни с Alibaba.</p> <p><strong>Нужен ли API-ключ?</strong> Нет. Вы один раз входите в свой аккаунт на нужном чате — DeepSeek (хранится в <code>~/.zames/profile</code>) или Qwen (хранится в <code>~/.zames/qwen-profile</code>) — и сессия переиспользуется. Qwen также работает в гостевом режиме на несколько сообщений.</p> <p><strong>Какую модель он использует?</strong> Ту, которую использует активный веб-чат. В DeepSeek это DeepSeek-V3 (или reasoning-модель при включённом «Deep thinking»). В Qwen модель можно выбрать командой <code>/model</code> (например, <code>qwen3.7-plus</code>). zames никогда не вызывает API напрямую.</p> <p><strong>Работает ли headless / на сервере?</strong> Да — headless по умолчанию, а <code>--output-format jsonl</code> делает его скриптуемым. <code>--headed</code> нужен только для ручного входа или отладки селекторов.</p> <p><strong>Разрешена ли автоматизация веб-интерфейса?</strong> Это зависит от условий сайта; автоматизация сайта может их нарушать. Используйте на свой риск и держите троттлинг отправки (15 с в DeepSeek по умолчанию), чтобы не бить по рейт-лимиту.</p> <p><strong>Чем отличается от Claude Code / Codex?</strong> Та же форма (инструменты, <code>AGENTS.md</code>, навыки, MCP, слэш-команды), но работает на вашем аккаунте DeepSeek или Qwen вместо API, как автоматизация браузера, а не first-party API-клиент.</p> <h2>Ссылки</h2> <ul> <li><strong>npm:</strong> <a href="https://www.npmjs.com/package/zames_pro">https://www.npmjs.com/package/zames_pro</a></li> <li><strong>GitHub:</strong> <a href="https://github.com/Viqto0r/zames_pro">https://github.com/Viqto0r/zames_pro</a></li> <li><strong>Changelog:</strong> <a href="CHANGELOG.md"><code>CHANGELOG.md</code></a></li> <li><strong>Contributing:</strong> <a href="CONTRIBUTING.md"><code>CONTRIBUTING.md</code></a></li> <li><strong>Security policy:</strong> <a href="SECURITY.md"><code>SECURITY.md</code></a></li> <li><strong>Code of conduct:</strong> <a href="CODE_OF_CONDUCT.md"><code>CODE_OF_CONDUCT.md</code></a></li> </ul> <h2>Лицензия</h2> <p>MIT</p> </details>
