An open, player-built database for World of Warcraft: Forever. An addon records what you see, and the site states a fact only once three installs agree.

Everloot is a fan project. WoW: Forever launches on 2026-11-04, and Everloot is built to have real answers on day one: drop rates, vendor prices, recipe ranges, spawn points, talent trees, what changed in the latest build. Players supply the observations. The site shows each fact with the number of installs that reported it and the date, and anyone can read the anonymous records behind the count.

It does not scrape other sites and never touches the running game. The addon uses the game's own addon API and writes its own save file. Everything that comes from the game files is labelled unconfirmed until players have seen it, and spoilers are hidden by default. The full rules are in docs/DATA_POLICY.md.

What is live on everloot.app

Database. Items, NPCs, quests, vendors, professions and auction history, built from player uploads. A figure appears once three installs report it, with the count and the data's age beside it. everloot.app/database

Talent calculator. Plan a build for any class: point rules, two talent sets, undo, and a share link that names the game build. The addon can load that plan and show you the next point to spend. everloot.app/tools/talents

Raid builder. Fill a 10, 20 or 40 player raid with classes and talent trees and see which buffs and debuffs each group and the raid gets. The plan lives in the link. everloot.app/tools/raid

World map. One map drawn by us from zone and entrance positions in the game files, with no game art. everloot.app/map

Change tracker. Blizzard staff posts, hotfixes and new game builds, newest first, with a link to the original and an RSS feed. everloot.app/changes

Lore archive. The Warcraft Wiki (CC BY-SA 4.0), browsable by type and searchable. everloot.app/lore

Addon leaderboard and profiles. Which addons Forever players run, for the players who opt in to share their list. A count appears only when three installs report it. everloot.app/addons/popular

Connect. How to use the open data from an AI assistant or your own code. everloot.app/connect

Market prices. Blizzard has no auction API for Forever, so prices come from full auction scans that players start with the addon's Everloot scan button. The site shows a realm table and a 60-day chart per item, a day is published once three reporters agree, and the same prices appear in item tooltips in game. everloot.app/tools/auctions

MCP server. 28 tools that let an AI assistant search the archive and read the same sourced facts the site shows: items, NPCs, quests, vendors, profession paths, recipe ranges, auction history, market values, recent Blizzard changes and more. The public endpoint is read only and rate limited: https://everloot.app/mcp/public.

Part What it does
addon/ The in-game collector (Lua) and the /ask command
web/ everloot.app: the database, tools, map, change tracker, lore archive, upload page and MCP endpoints (Next.js on Vercel)
kb/ The knowledge base: lore import, public releases, the game-file extractor and the MCP server (TypeScript, SQLite)
companion/ A desktop helper that uploads your file and answers /ask in game
desktop/ Everloot Desktop App: the same, as a tray app with an installer

supabase/ The site's database schema

Quick start

Players

  1. Download the addon from everloot.app/upload and extract Everloot/ into the game's Interface/AddOns/.
  2. Play. Log out, or type /reload, to save.
  3. Upload WTF/Account/<account>/SavedVariables/Everloot.lua at everloot.app/upload. You preview everything before it is sent.

Or install the Everloot Desktop App (download): it uploads after every logout and can install and update the addon for you.

Auction capture and the list of your installed addons are off until you turn them on (/everloot auctions on, /everloot addons on). To see market prices in item tooltips, the companion writes them into the game folder (prices --game); the addon's scan button on the auction house adds your own scan.

Developers

You need Node 22 and Python 3.12 (for the addon tests).

git clone https://github.com/Everloot/everloot.git
cd everloot
(cd kb && npm install)
cd web && npm install
npm run sample-release   # prints a KB_SNAPSHOT_PATH line: put it in web/.env.local
npm run dev              # http://localhost:3000

The sample release gives you about 35 lore pages to work with. Pages that need storage say it is unavailable, which is expected locally. Each part's README has its test commands, and CONTRIBUTING.md lists what CI runs.

AI-assistant users

Point any MCP client at the public endpoint:

claude mcp add --transport http everloot https://everloot.app/mcp/public

or put { "mcpServers": { "everloot": { "type": "http", "url": "https://everloot.app/mcp/public" } } } in the client's config. The connect page lists every tool with its arguments and every JSON endpoint, the rate limit and how to credit the data. The API is described in /api/openapi.json (OpenAPI 3.1) and the protocol's JSON Schema files are under /schema/.

Project status

Beta. The addon is at 0.3.3 and passes its automated tests; the in-client checks in docs/2026-10-08-beta-client-checklist.md and docs/2026-10-18-addon-0.3.2-beta-checklist.md and docs/2026-10-19-addon-0.3.3-beta-checklist.md are still open until the game is playable. The game-file layers (talents, raid buffs, map) are read from build 1.60.1.70450 and marked unconfirmed. A build watch checks for new builds every half hour and opens a reviewed pull request when one appears. WoW: Forever launches on 2026-11-04.

What is next is in ROADMAP.md. What has shipped is in CHANGELOG.md. Nightly pre-releases of the addon are on the releases page.

How to help

You don't need to write code. Playing with the addon and uploading, or reporting a wrong fact, helps as much as a pull request.

  • Questions and ideas: GitHub Discussions
  • Bugs and wrong data: issues
  • A first code contribution: issues labelled good first issue
  • Chat: the Everloot Discord
  • Security problems: SECURITY.md, never a public issue

Read CONTRIBUTING.md first: it covers sign-off (git commit -s), pull request titles and the data rules.
