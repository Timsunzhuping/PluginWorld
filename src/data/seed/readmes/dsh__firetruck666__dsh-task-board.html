任务看板（dsh-task-board）

English | 中文

DeepSeek Harness 的任务看板插件。它在 Web 界面的侧边栏加一个「任务看板」入口，用五列看板管理任务；任务交给 DSH 自己的会话真实执行，状态自动回写到卡片上。

插件不修改 DSH 源码，卸载后界面恢复原状。看板数据保存在 DSH 主进程（host）一侧，电脑和手机打开同一个部署看到的是同一块板，改动经 SSE 实时同步；窄屏自动进入紧凑布局。

环境要求

  • DeepSeek Harness 0.1.7-rc.2 或更高。0.1.7-rc.2 是最低支持版本，不是「当前版本」：低于它的没验证过，上限不设——插件跟着 DSH 更新，升级 DSH 之后装最新版即可。加载失败时先按「常见问题」里的说明处理。
  • Node.js ^22.19.0 或 >= 24.0.0
  • pnpm 10 或更高
  • DSH 的 web profile

本插件只运行在 Web 图形界面上。

安装

三种方式，选一种。三条命令都在你自己的终端里执行。桌面端（DSH 桌面应用）不用敲命令：在它的「插件」页里添加同一个包名即可——那个 profile 由应用自己管理。

从 npm 安装

dsh plugin --profile web add @firetruck666/dsh-task-board

适合日常使用。拿到的是最近一次正式发布的版本。

从 GitHub 安装

dsh plugin --profile web add github:FiretrUCK666/dsh-task-board

拿到的是仓库 main 分支的最新代码。它和 npm 装出来的一样是可直接使用的安装包，不是开发环境（没有测试、没有构建工具，改不了代码）。适合想第一时间用上还没发版改动的人；稳定性取决于仓库当时的状态。

本地开发安装

把仓库下载到本地后，在这个仓库目录里执行：

pnpm install
pnpm build
dsh plugin --profile web add .

这条路径用于改代码。详见下面的「从源码构建」。

本地安装是指向工作目录的链接（不是复制），所以挂载一次即可：改完代码只需 pnpm build 再重启 dsh web，不必重跑上面的安装命令。改 client 半区刷新页面即可，改 host 半区才需要重启——见「常见问题」里的「改了代码没生效」。

三种方式的区别

前两种是安装：拿到的都是可以直接使用的包，只包含发布清单里的文件（运行代码、源码、挂载声明、说明文档），差别只在版本新旧。第三种是开发：拿到的是完整仓库，能改代码、能运行测试。

从 npm 从 GitHub 本地
用途 安装使用 安装使用 开发
拿到什么 最近一次发布版 main 最新代码 你本地改动
版本特点 稳定 最新，可能不稳定 你自己决定
更新依据 npm 上的版本号 仓库最新提交 安装的即本地目录，无需更新

安装之后

停掉正在运行的 dsh web，重新启动它，然后刷新页面。只刷新页面不够——插件的 host 半区在服务端进程里加载，必须重启才生效。重启后侧边栏就会出现「任务看板」入口。

入口和 DSH 自带的「插件」面板并排：点它，看板占用中间主区域；再点一次同一个入口、或点侧边栏里的任意会话，即可回到对话。

这个插件的开关在两处，各管各的：侧边栏「插件」→ 往下拉到「已安装」，那一行右边的开关是总开关； 或点开「任务看板」进它自己的页面，右上角那个开关做的是同一件事。关掉 = 整个插件不加载 （侧边栏入口、看板、清单、后台接口一起停）。页面里「包含的组件」下面还有四行， 每行一个开关，管各自那一半（看板 / 清单 / AI 接口）——详见「常见问题」。

不需要手动配置任何东西

装完就能用，不用改配置文件、不用手写任何声明。而且不要去改 cordis.patch.yml——插件那一行住在插件包里，安装命令只负责把这个包登记进 profile，两者一配合就装配好了；手工再补一行会造成同一个插件出现两条。

环节 谁做的
把插件登记进本机 profile 安装命令（往 dsh.profile.bundles 加一个包名）
插件那一行（id、包名） 插件包里的 cordis.patch.yml，由 package.json 的 dsh.bundle.patch 指向，装配时自动生效
界面入口、看板舞台 插件自己注册到 DSH 的官方扩展点，启动时自动完成
数据存哪 自动使用 ~/.dsh/storages/dsh_task_board/ 目录，第一次运行时创建
插件显示的名字、说明、图标 包里的 locale/ 与 icon.svg，DSH 直接读取
那个开关的位置 插件管理页的开关写 profile 里这一行的 disabled（关掉时才会写上）

唯一必须你做的一步是重启 dsh web（host 半区在服务端进程里，不重启不会加载）。三种安装方式（npm、GitHub、本地）在这件事上完全一样。

这个插件没有设置项，也不需要设置面板：看板的行为（任务、定时、巡航、规则）全在看板界面上直接编辑，而开与关就是上面那个开关。

卸载：

dsh plugin --profile web remove @firetruck666/dsh-task-board

同样需要重启 dsh web。卸载不会删除你的任务数据。

更新

看板 Header 右侧工具栏里有常驻的「检查更新」按钮，点一下即对比当前版本与最新版；有新版时它开一个「版本更新」对话框。

对话框里的「一键更新」知道自己该做什么，因为它读的是你正在运行的那一份的安装来源：安装方式与所属 profile 都从那一份所在的 profile 清单里读出来——所以同一台机器上 Web 端装的是本地开发、桌面端装的是 npm，两边各说各的，不会互相认错。

安装方式 「一键更新」做什么
从 npm 安装 按 npm 上的最新版本重装这一个包
从 GitHub 安装 按仓库 main 的当前提交重装
本地开发安装 在仓库目录里 git pull --ff-only，再按仓库自己声明的包管理器重建 lib/
桌面端里装的 交给桌面端做（它的 profile 只能由它自己管理）

更新完：能热载入的就地生效，需要重启的对话框会说明。任务数据任何时候都不受影响。

对话框里同时给出等价的终端命令，命令里的 profile 名就是你的那一份。命令也可以手动执行（把 <profile> 换成你自己的，一般是 web）：

dsh plugin --profile <profile> add @firetruck666/dsh-task-board@latest

dsh plugin --profile <profile> add github:FiretrUCK666/dsh-task-board

本地开发安装则是：

git pull --ff-only && pnpm run build

装了插件市场的话，也可以在它的「已安装」标签页里点「更新」。

桌面端：插件装在那个应用自己的 profile 里，而那个 profile 由应用托管——终端里的 dsh plugin --profile desktop 会被拒。在对话框里按「一键更新」，或在应用的「插件」页里重新添加，然后完全退出应用再打开。

主要能力

任务看板

  • 五列：待规划 / 待办 / 进行中 / 待审核 / 已完成。卡片可以拖到别的列，同一列里也能上下拖，指定先后。
  • 执行是真的：在详情里点「执行」，DSH 会话开始干活，跑完自动落到「待审核」。跑过几次、上次成没成，卡片上写着。
  • AI 正在跑的卡有黄边，还没读过的有外环。
  • 板顶一行数字：几个在等你、几张待审核。点它开通知中心。
  • 通知中心收着所有等你处理的事；动态页按日分组，看最近发生了什么。
  • 复核页是一次执行的完整记录，可以直接「通过 / 打回」。
  • AI 在评论区里提问，当场就能答；计划待审那张卡也一样——「同意执行」直接作答，「要求修改」把它退回输入框，不必先去会话里走一趟。（哪台机器的宿主不提供就地作答时，那张卡会引用会话给的选项、说清为什么这里答不了，只留一扇「去会话回答」的门。）
  • 每张卡的评论区就是它的 DSH 会话。排队发、插话发都行，图片和文件直接拖进去。
  • 把侧栏里的会话或工作区拖到某一列，就得到一张绑好关系的卡。
  • 定时跑、跑完接着跑、给某个会话按时间表发指令——两种自动化各管各的；发出去的指令可以带图片和文件，规则那一行会写明带了几个。
  • 自动巡航：板头一颗开关，设好同时最多几件、哪些时段跑。
  • 多选之后，改色、执行、删除一次做完。
  • 详情能存成模板，新建时选一个就填好了；运行配置能存预设、设默认。
  • 窄屏上列变成横向滑动，功能不少。

任务清单

  • 按「＋新建一条」记一件事：标题在最上面，下面依次是正文、步骤、上下文备注（正文还可以拖进图片和文件）。左列写内容，右列定属性——优先级、状态、标签、三个日期、挂到哪张卡。挂到哪张卡有三个选择：不挂（先记下来，以后再说）、挂到已有的卡（那张卡里的内容一个字都不动）、新建卡片——选了新建，你会先看到这张卡要用什么跑（工作区 / Agent / 模型 / 思考程度 / 权限），它带着你看到的那一份出生，之后在卡上或这一行的详情里改。
  • 清单是独立的，不必先变成卡片；挂上卡之后，它显示的状态就跟着那张卡在哪一栏走。
  • 一行自己的状态是五档（待规划 / 待办 / 进行中 / 待审核 / 已完成），词与色都用看板那一套。没挂卡时五档随你选；挂着卡时跟着那张卡走，但你自己按下的「已完成」压过卡片——一件已经做完的事，不会因为卡还在跑就变回没做完。按那一枚状态芯片会跳到看板并打开它挂着的卡。
  • 「问 AI」是这一页唯一交给 AI 的一按，没挂卡的条目也能按：那张卡已经有对话就接着说进那条对话，还没有就开一轮——由卡自己决定，你不用挑。送过去的是这一条自己的内容（标题、标签、正文、步骤、备注，以及正文带的图片与文件），不是卡上的执行 Prompt，所以卡自己的 Prompt 是空的也照样问得出去。没挂卡的会先就地建一张卡，卡就带着你眼前那一份运行配置出生——所以配置不是按下去那一刻才冒出来问你的东西：详情右栏那块「运行配置」一直在，展开就是那五行（工作区 / Agent / 模型 / 思考程度 / 权限），点「改」就地换，按下去跑的就是屏上那一份。
  • 看板那张卡片上有一枚「挂 N 条 · 最急：X」，按它跳到清单并只看挂着这张卡的条目（那是一枚筛选项，看得见也摘得掉）。
  • 三个时间各自独立：开始、计划、截止——每个日期框的名字旁边都有一句注解（早于这天不动 / 想做完的那天 / 不能顺延的那天），展开详情里点开那一行时同样看得到。只有错过截止才变红，那一行写「超期 N 天」；计划滑了是黄的，写「落后 N 天」——承诺失守和计划推迟是两回事。
  • 步骤打勾出进度条，优先级四档，标签随手打。
  • 筛选全在左栏：日历、按日期（日期已过 / 日期未到 / 没定日期）、按多久没动（放着没动）、优先级、状态、日程、已删除。每一项都带数字，0 也写。
  • 左栏顶上的日历能翻月、能回到今天，也能折成一行——翻月与回到今天是同一个控件里的三格（同一条边上的 ‹ / 回到今天 / ›），「回到今天」没路可回时变灰、不消失。点某一天只看那天，搜索框下面会留下一枚能按掉的日期芯片——空列表也说得清是为什么空。
  • 状态那一栏与看板是同一套词、同一套颜色：待规划 / 待办 / 进行中 / 待审核 / 已完成。行自己只存两个值（还没做、做完了），挂上卡之后跟着卡在哪一栏走；行首那颗珠子说这两个值，颜色说它在哪一栏。那一枚状态芯片按得动：按它就跳到看板、打开它挂着的那张卡。
  • 标题、正文、备注、日期都在这一行里改，不另开窗口；运行配置也在这一行里（详情右栏那一块），而且它显示的正是这一次要用的那一份：挂着卡时是那张卡的（改的也是那张卡，与看板是同一处设置，不是第二份），还没挂卡时是「这一次要交给它的那一份」——那一块会说明它会跟着新卡走，之后在卡上改。
  • 写正文和备注的框，高度是你自己的：它不会随你打字自己长高，装不下就在框里滚；抓住整条下沿就能拉高拉低，拉完就记住（同一台设备上「新建一条」里那三个框也是这个高度）。下沿那条握痕一直画着，键盘也能用上下箭头拉。
  • 正文可以带图片和文件：拖进去，或者点「＋」。它们随这一条保存，变成卡片时一起过去；行上有一枚回形针，写着这一条带了几个。
  • 日期写错不会悄悄消失：@明天、10月15日、2026-10-15、10/15、Oct 15 都认；读不懂的三种情形各有各的说法——写法不认识就教你再试一次（2026-10-15、明天、周三、+3），只写了日子没写年份而那天今年已过就让你把年份补上（猜一个等于把一天挪一年），日历上没有那一天（2026-02-30）就让你核对月份与日期。而你已经写下的日期一个字都不动。
  • 日程页按天读，节名与行尾是同一套词：截止已过 / 计划已过 / 今天 / 明天 / 一周内 / 以后——「截止已过」说的是最后期限那天，「计划已过」说的是你打算做完的那天。一节有行才占一节；空的几天、以及没排进来的（已完成的、刚记下的）都在末尾那一行里带着数字说清楚。没写日期的进「没定日期」，开始日还没到的等在「还没开始」——答不出「它为什么在这一页」的那几节各带一枚圆圈 i（截止已过 / 计划已过 / 没定日期 / 还没开始），末尾那一行也带一枚；指着它或者按它，才会出现一句解释。按天的节（今天 / 明天 / 一周内 / 以后）不带——它的名字就是那一天。
  • 删除有撤销；删掉的都在左栏底部「已删除」，30 天内能找回，也能彻底删除。
  • 多选之后，改状态、设优先级、排在今天、问 AI、删除一次做完。
  • 键盘：A 新建、J/K 移动、X 多选、1–4 优先级、E 改标题、⌘Z 撤销、Esc 一层一层收。

多台设备与 AI 入口

  • 数据存在这台机器的 ~/.dsh/storages/dsh_task_board/，人可读。换机器，拷这个目录就行。
  • 手机上打开是同一份数据。断网也能用，连上后自动对齐。
  • /task 把你写的话交给当前会话的模型；/task-continue 让它接着上次往下做。

数据保存在哪里

  • 看板真相：~/.dsh/storages/dsh_task_board/ 目录。documents/ 下每种数据一个文件：board.json 是任务台账、巡航、定时预设、运行配置预设与删除墓碑；items.json 是任务清单。人可读、原子写入，可以直接整目录备份；删除这个目录等于清空看板与清单。
  • 浏览器 localStorage 保存离线镜像和本地状态。两份承载数据的镜像是 dsh.taskBoard.v1（看板）与 dsh.taskBoard.items.v1（任务清单）—— 两份都要备，只备一份等于清单那份丢了。其余的键 （cruise / presets / runPresets / templates / drafts / preSync）是这个浏览器自己的状态或 一次性备份，不是另一份真相。键名以 src/client/ 里实际写下的为准；这里列的是哪些值得你 操心，不是全部键的清单。
  • 第一次连接时如果本地数据与 host 有分歧，本地副本备份到 dsh.taskBoard.preSync.v1，host 为准。
  • host 没有挂载存储后端时，看板自动退回纯 localStorage 模式。

从源码构建

前置：Node.js 22 或 24、pnpm、能访问官方 npm 源（类型和运行时 API 全部来自 @deepseek-ai/*，不需要 DSH 源码 checkout）。

git clone https://github.com/FiretrUCK666/dsh-task-board.git
cd dsh-task-board
pnpm install
pnpm build       # 产出 lib/index.js 和 lib/client.js
pnpm typecheck   # 类型检查
pnpm test        # 单元与契约测试
pnpm verify      # 独立插件静态门禁

lib/ 是构建产物，但它随仓库一起提交。原因是从 GitHub 或 npm 安装时只会复制文件，不会执行构建，仓库里没有 lib/ 的话装完就启动不了。改完源码要重新构建，并把 lib/ 和源码放在同一次提交里（CI 会检查两者是否一致）。

仓库根目录的 AGENTS.md 记录了项目的约定、架构索引与发布流程，是 AI 助手在这个仓库里工作时用的依据。

贡献指南

欢迎提 Issue 与 Pull Request。动手前先读 CONTRIBUTING.md：开发环境、提交 PR 前要跑的检查、硬性规范都在里面。报告加载失败类问题时，附上三个信息：DeepSeek Harness 版本、本插件版本、报错原文。

常见问题

插件页面上的四个开关是什么。 侧边栏「插件」→ 已安装 → 点「任务看板」→「包含的组件」列出四行，每行一个开关：

那一行 关掉之后
任务看板 侧栏面板列表里没有「任务看板」，看板面板不再出现
任务清单 侧栏面板列表里没有「任务清单」，清单面板不再出现
AI 接口 所有会话的 AI 都看不到本插件的工具、斜杠命令与系统提示——它们从未被注册，不是被拒绝
任务看板（插件本体） 整个插件不加载，上面三行随之无意义

「AI 接口」这一行是装配层的开关：关掉它，插件的那几个模块根本不加载，所以没有任何一次运行 时判断可以漏掉。清单与看板各自要开关，是因为它们是两个界面；而一个 npm 包只有一份浏览器产物， 所以这两行由宿主侧的模块宣告，浏览器开机时读一次。

看板上的状态词都什么意思。 它们读的是同一份推导，所以同一张卡在任何一处都是同一个答案：

你看到的词 它在说什么 什么时候消失
待你决断（失败时写「失败待决断」） 卡在「待审核」列，有跑完但那个会话你还没看过的结果 打开那个会话的评论区，或点「通过 / 打回」

「待你决断」和「新 N」是两件事：「新」是「这张卡你没打开过」，「待你决断」是「那个会话你没 看过、也还没裁决」。取消不算「待你决断」——取消是中止，它只出现在评论线程和动态里。

装完刷新页面看不到入口。 host 半区在服务端进程里加载，必须重启 dsh web，只刷新页面不够。

入口在哪、开关在哪。 看板与清单是侧边栏里的两个面板图标，与 DSH 自带的「插件」面板并排。 这个插件的开关就在插件自己的页面上：侧边栏「插件」→ 已安装 → 点「任务看板」， 四行分别是看板、清单、AI 接口与宿主半区，每行一个开关，关掉哪行哪一半就不注册。 如果你看不到入口，说明这一端还在跑旧的前端资源——刷新页面即可。

升级 DeepSeek Harness 之后插件加载失败（页面提示 Failed to load plugins）。 DeepSeek Harness 的内部接口会随版本变化，本插件需要跟着改。先做这两步：

  1. 把本插件更新到最新版，然后重启 dsh web：

    dsh plugin --profile web add @firetruck666/dsh-task-board@latest

  2. 仍然失败，说明本插件还没跟上你用的那个 DSH 版本。请到 Issues 提交，附上三个信息：你的 DeepSeek Harness 版本、本插件版本（在插件页的「已安装」列表里看——不是设置页，本插件没有设置项）、页面上那段报错原文。有这三样就能直接定位。

看板能打开，但多设备不同步、任务清单也一直是空的。 这是 host 半区没加载成功的表现，也是升级 DSH 之后最容易被忽略的一种：看板本身仍在页面上正常工作，但数据只留在这一个浏览器里，另一台设备看到的不是同一块板，定时与巡航也不会真正触发。任务清单在这种情况下会明说「暂时读不到 host 上的清单，正在用本机的副本」，不会假装自己一条都没有。处理方式与上一条相同——更新插件、重启 dsh web。

打开右侧栏之后看板变了样子。 这是正常的响应式行为，不是故障。DSH 的右侧栏默认占视口约 45%、最少 300px，中栏硬保 400px，所以打开它之后中间那块板本身变窄了：看板的响应式看的是自己盒子的宽度（不是窗口宽度），板盒一旦窄过它的紧凑档阈值，五列就会变成横向滑动的列轨、并出现五等分的列导航标签。把右侧栏收回去就恢复。这条规则本意就是「板盒多宽就摆多宽」，侧栏开合、分屏、手机上都成立。

改了代码没生效。 改 host 半区（src/index.ts、src/host/）需要重启 dsh web；改 client 半区刷新页面即可。两种情况都要先 pnpm build。

手机上打开位置不对，或反复开合侧栏会跳位。 这是修复过的问题。如果仍然出现，先确认服务端进程是重启过的新版本：插件在板头会显示「服务端未重启 · 点此了解」，点开可以看到当前连接的服务端进程的启动时间。如果时间明显是旧的，说明这个地址连到了另一个没重启的实例。

两端同时开着会不会重复执行定时任务。 不会。定时、巡航、接续这类行为由 host 租约仲裁，同一时刻只有一个界面在执行，另一台设备切到前台后会接管并补上期间漏掉的状态。

任务数据在哪，换电脑会丢吗。 在 ~/.dsh/storages/dsh_task_board/ 目录。换电脑时把整个目录拷过去即可；浏览器里的 localStorage 只是离线镜像。

找不到任务清单的入口。 清单是侧栏面板列表里紧跟「任务看板」的第二行——把左栏展开就能看到两行图标，点第二行打开清单， 再点一下回到会话。侧栏收成一条窄图标带时，两行挨着排在一起。

如果那一行根本没有：多半是这一端还在跑旧的前端资源，刷新页面即可；还不行就去看插件页上 「任务清单」那个开关是不是被关了（见上面「四个开关」）。清单关掉不影响看板。

切到看板面板时清单不见了。 那不是坏了，是主舞台一次只显示一个面板——它本来就是这么设计的，不是两个能同屏的东西。 想回清单，点侧栏里清单那一行；想回对话，点「返回对话」或再点一次当前那一行。

dsh plugin 报错找不到 pnpm。 先安装 pnpm（npm install -g pnpm），再重新执行安装命令。

命名约定

用途 值
插件 id dsh-task-board
npm 包名 @firetruck666/dsh-task-board
权限预设路由 /api/dsh-task-board/permissions
看板数据路由 /api/dsh-task-board/board（含 /items、/surfaces、/lease、/command、/events）
其余 host 路由 /api/dsh-task-board/session-state、/update、/client-report
host 存储单元 dsh_task_board（documents/ 下每种数据一个文件）
看板舞台 slot main（key: dsh-task-board）
任务清单舞台 slot main（key: dsh-task-board-items，与看板同一个座位、不同键）
侧栏入口 slot sidebar.panellist（id 与各自的 main 键一致）
localStorage 键 dsh.taskBoard.v1 等

插件 id 和包名是两件事：id 决定加载器行、浏览器资源路径、路由、存储单元和上面那几个扩展点；包名只是 pnpm 安装时的标识。包名带作用域不会改变 id。

本插件没有设置项，所以也没有设置路由和设置面板：插件市场里那条开关写的是 profile 行的 disabled（关掉时才写上），插件本身不声明任何设置字段。
